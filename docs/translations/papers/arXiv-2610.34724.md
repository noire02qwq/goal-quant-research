## 摘要

长时程智能体（long-horizon agent）在运行中会不断遇到可复用的程序性知识，但现有系统要么依赖模型适配，要么依赖外部记忆，往往以牺牲持久学习来换取快速复用。这一局限对反复执行相关多步工作流的 Web agent 尤为关键。我们提出 HaMo——一个 Harness–Model 协作框架，把快速的非参数经验积累与缓慢的参数化适配结合起来。

HaMo 将轨迹蒸馏为策略级经验卡（strategy-level experience card）以便即时检索；同时用一个经验条件化（experience-conditioned）的持续学习目标训练模型，使其能在不断变化的上下文中解读、落地并执行检索到的策略。此外，一个基于检索覆盖率的选择机制会挑出紧凑且互补的轨迹来做参数更新。实验表明，在域内与跨域偏移下，HaMo 都优于只用 harness 和只用模型的适配方式，同时改善了保持能力与适配能力。这些结果凸显了这样一点：既要保留程序性经验，也要把跨任务迁移与执行这份经验的能力内化。

## 1 引言

今天能完成长时程任务的智能体，明天应当更擅长解决相关任务。长时程交互自然会产生可复用的程序性知识 [13, 36]，但缺乏显式跨任务学习机制的智能体会把每个任务当作孤立的一次回合，无法随时间系统地积累这类经验。这一局限对 Web agent 尤为重要：它们反复执行信息检索、商品搜索、交易类任务等多步工作流 [3, 5, 8]，而以往交互中获得的知识本可以直接造福后续任务。

一个自然的思路是模型层适配，即用先前任务的轨迹更新模型参数 [2, 16, 29]。这类更新能把过去的交互变成持久的行为能力，但频繁适配代价高昂，还可能干扰已获得的能力，尤其是在顺序分布偏移（distribution shift）下 [12, 26]。另一种选择是 harness 层适配：把有用的经验存到外部，供未来任务检索使用 [15, 37]。这让新获得的知识无需重训练就能立刻影响行为，但模型本身未必会变得更擅长解读和执行检索来的经验。仅靠其中任何一种机制，都无法真正解决长时程智能体的持续学习问题（见图 1）。

> 图 1：长时程智能体持续学习中本方法的动机。只用 harness 或只用模型的方法，要么能快速复用经验但容易进入平台期，要么不稳定且发生遗忘。HaMo 结合两种机制，在领域内实现稳步提升，并在跨域偏移下获得更好的保持。

我们认为这两种适配形式天然互补，因为它们运行在不同的时间尺度上。从单条轨迹中发现的策略，可能对未来的任务已经有用，但同时又过于具体，不足以支撑一次即时的参数更新。这类知识可以先存到外部，等类似情况出现时再复用。随着相关策略在不同任务中反复出现，它们为改进模型本身提供了更强的监督信号。对长时程智能体而言，这个过程并不只是记住过去的解法：关键挑战在于把程序性能力内化——也就是解读高层策略、在变化的环境中将其落地（ground）、并转化为恰当行动的能力。

受此启发，我们提出 HaMo，一个面向长时程智能体持续学习的 Harness–Model 协作框架。我们的方法把适配拆成两个紧密耦合的过程。在 harness 层，每条轨迹被蒸馏成一张紧凑的经验卡，其中包含任务上下文、初始条件和策略级的解法提纲；这些卡存入持久的非参数记忆，让新获得的程序性知识立即可被未来任务取用。在模型层，HaMo 用被选中的轨迹连同历史回放（replay）持续更新一个参数高效 adapter，在利用积累经验的同时保持既有能力。

HaMo 的一个关键设计是经验条件化的适配。模型不只是学习从交互上下文到动作的直接映射，还额外以从 harness 检索到的策略级经验为条件，因此学会在不同的观测、对象、状态和交互历史下，如何解读并实例化一条检索到的策略。推理时使用同一个接口：harness 负责检索相关经验，被适配的模型则决定这份经验该如何在当前环境中执行。如此一来，harness 保存可复用的程序性知识，而模型适配逐步内化跨任务迁移与执行这些知识所需的能力。

HaMo 还处理了持续监督的冗余问题。把经验存到外部成本很低，但对每条观测到的轨迹都重复训练并无必要，因为许多轨迹编码的是相似的策略。因此我们引入基于检索覆盖率的选择机制，挑出一小批有代表性、彼此互补的轨迹来做参数适配。一条经验若能通过检索支撑许多其他任务，就会被优先选中；同时我们鼓励被选集合覆盖各不相同的策略上下文。这样参数更新就集中在广泛可复用的程序性知识上，而不必让所有存下来的轨迹都参与训练。

我们在 ScienceWorld、ALFWorld、WebShop 上以持续的长时程任务流评估 HaMo，覆盖域内与跨域两种设置。WebShop 提供交互式 Web agent 环境，其余基准用于检验所提学习机制能否泛化到单一领域之外。结果显示，harness 层适配与模型层适配之间存在清晰的互补关系：只用 harness 的学习能快速复用经验，但会碰到性能天花板；只做模型适配能获得很强的任务特化能力，却在分布偏移下发生严重遗忘。HaMo 结合两者优势，实现了更强的持续适配，同时更好地保持了既有能力。

## 2 相关工作

### 2.1 面向长时程任务的 LLM

长时程智能体必须在漫长且容易失败的轨迹上保持目标导向行为 [4]。已有工作从多个方向改进推理、规划与网页交互：推理–动作交错 [31]、有状态基准 [40]、系统级分析 [14]、搜索与反思 [39]、动作知识 [41]、全局规划 [20]，以及基于课程的强化学习 [9, 10]。互补的工作则通过轨迹压缩 [32]、rollout 聚合 [11]、全局记忆 [17]、可复用工作流 [28] 和条件化记忆 [1] 来改进经验复用。我们关注的则是另一件事：在持续的长时程任务流中保留并巩固可复用的经验。

### 2.2 LLM 智能体的持续学习

外部记忆方法保留语言反馈、技能、工作流或结构化记忆，而不频繁更新权重 [7, 18, 24, 28, 34, 38]。基于参数的持续学习则通过参数保护、回放 [22]、持续策略适配 [25] 或多个保持锚点 [35] 来缓解遗忘。然而，这两条路线都没有直接决定：哪些经验应当继续留在外部可检索，哪些应当驱动参数更新。

EvolvingAgent [6] 把演化经验与持续世界模型学习结合起来，Dong 等人 [4] 则强调了外部经验与内化能力之间更广泛的联系。HaMo 协调这两个时间尺度：快速更新的策略级记忆支持即时复用，被选中的轨迹与回放则让参数适配不必那么频繁。

## 3 方法

HaMo 通过两个工作在不同层面的互补机制来协调持续学习：harness 层的持久外部记忆，以及模型层的持续参数适配。harness 保留可复用的策略级经验，让新获得的知识无需参数更新即可立即访问；模型则被持续适配，以解读检索到的经验、把它落到当前交互上下文中、并转化为恰当的行动。训练与推理共享同一种初始对话格式：用户请求、初始观测，以及注入的匹配经验。

### 3.1 harness 层记忆

长时程轨迹包含的不只是孤立的状态–动作对，它们往往编码了可复用的计划、中间子目标，以及应对反复出现情境的策略。因此，在把每条专家轨迹用于持续学习之前，我们先把它转换为紧凑的策略级表示。对阶段 t 观测到的轨迹 τ_i ∈ D_t，我们用大语言模型提取解法提纲 z_i。提纲与相应的任务描述 g_i、初始可观测条件 o_i^0 组合，构成一张经验卡：

    c_i = (g_i, o_i^0, z_i)                              (1)

![图2：HaMo 框架总览](原文图片位置：第 3 页 Figure 2)
> 图 2：HaMo 框架总览。HaMo 持续把专家轨迹蒸馏为持久的 harness 记忆，基于检索覆盖率选出有代表性的锚点轨迹，并与历史回放结合，通过经验条件化的行为克隆更新一个 LoRA adapter。适配之后有一个可选的反馈步骤，释放与已训练高质量轨迹相关的记忆条目。这种协作使 harness 层快速复用经验、模型层逐步内化知识成为可能。

从 D_t 中各轨迹提取出的卡构成阶段 t 的集合 C_t。每张卡与其来源轨迹一一对应，使被选中的经验可以映射回它所提取的那条轨迹。

当前阶段观测到的所有经验卡首先加入外部 harness：

    M_t = M_{t-1} ∪ C_t                                 (2)

其中 M_t 表示加入新卡之后的阶段 t 记忆，M_{t-1} 是上一阶段保留下来的记忆。这个式子描述的是累积；其后还会应用可选的训练后释放（post-training release）。在 HaMo 中，持久存储与轨迹选择服务于不同目的：前者决定哪些历史策略继续对外可访问，后者决定哪些轨迹为当前参数更新提供监督。因此，未被选中参与训练的经验并不会从记忆中移除，之后的阶段仍然检索得到它。

虽然相对反复训练模型，在 harness 中保留经验的代价很低，但用每条新观测到的轨迹去做参数适配既无必要，也可能带来大量冗余：多条轨迹可能编码相似的策略，从而让模型暴露在几乎相同的训练上下文中。我们要找的是一个紧凑子集，其经验对当前阶段观测到的策略能提供广泛而互补的覆盖。

为了估计一条经验的复用范围，我们对经验卡的文本内容做 embedding，并在候选集合内做留一检索（leave-one-out retrieval）。对每张查询卡 i，在排除它自身之后检索其三个最近邻，记这些邻居的下标为 N3(i)。随后我们反转这一检索关系：对每张候选卡 j，令

    R_j = {i | j ∈ N3(i)}                              (3)

其中 R_j 包含那些把 j 检索为相关邻居的查询卡。它的基数

    n_hits(j) = |R_j|                                  (4)

衡量卡 j 所代表的策略能够潜在支撑其他轨迹的频繁程度。

不过，仅凭高检索次数并不足以找出有用的训练子集：两张经常被检索的卡可能支撑几乎相同的查询集合，同时选中它们带来的额外监督很少。因此我们按互补的检索覆盖率来选择经验。令 S 表示被选卡的下标集合，S 覆盖的查询集合为

    F(S) = ⋃_{j∈S} R_j                                (5)

对一个新候选 j，它相对当前选择的额外覆盖为

    Δ(j | S) = R_j \ ⋃_{s∈S} R_s                      (6)

从空集开始，我们贪心地选取 |Δ(j | S)| 最大的候选，并用惰性优先队列更新，避免每一步都重算所有候选的边际覆盖。这个准则偏爱广泛可复用的经验；同时，当某些低频经验覆盖了当前选择所没有的策略上下文时，仍会把它们保留下来。

选择过程一直持续到最大边际覆盖降为零为止，并把由此得到的覆盖饱和曲线记录为被选卡数量的函数。曲线上的一个拐点（knee point）决定该阶段的训练预算 N_t*。前 N_t* 张被选卡再映射回各自的源轨迹，得到阶段 t 的锚点集合 A_t。要注意，这个流程只用来为模型适配整理监督信号：适配期间所有经验卡都可用，包括那些轨迹不在 A_t 中的卡。训练之后，可以执行一个可选的反馈步骤来释放与已训练轨迹相关的条目，见 3.2 节。

### 3.2 模型层适配

外部 harness 提供对既往策略的持久访问，但仅有记忆并不能保证智能体成功地把检索到的策略用到新的交互上。一条存下来的解法提纲，可能提取自对象、观测或中间状态都不相同的轨迹。因此模型必须学会一种条件化的执行能力：给定策略级经验，它应当把这份经验落到当前环境中，并转化为适合不断演化的交互的行动。

HaMo 通过以检索到的经验为条件，显式地学习这种能力。令 B_t^old 表示从先前遇到的任务中采样、用于回放的轨迹；它与新选出的锚点轨迹一起构成阶段 t 的训练集合：

    B_t = A_t ∪ B_t^old                               (7)

新的锚点轨迹为适配新到来的任务提供监督，历史轨迹则继续让模型接触先前阶段获得的行为。

对每条轨迹 τ_i ∈ B_t，令 E_i 表示 harness 为该轨迹检索或匹配到的经验。初始对话由用户请求 g_i、初始观测 o_i^0 和注入的经验 E_i 组成，输入格式与测试时相同。后续决策还额外以不断演化的交互历史为条件。令 h_{i,k} 表示轨迹 τ_i 第 k 个动作之前的交互历史，a_{i,k} 表示相应的专家动作。我们优化经验条件化的行为克隆目标：

    L_t(θ) = −(1/|B_t|) Σ_{τ_i∈B_t} Σ_k log π_θ(a_{i,k} | g_i, o_i^0, h_{i,k}, E_i)   (8)

对文本动作，条件动作似然按相应的动作 token 分解。

E_i 在模型层适配中处于核心地位。传统的轨迹监督主要学习从当前任务上下文到动作的直接映射；相比之下，上面这个目标显式训练模型在 harness 额外提供的策略上下文下行动。因此，模型不必在参数中逐一复现每条存下来的策略；参数学习聚焦于获得一种可复用的能力——解读策略级指导，并在不断变化的对象、观测、状态和交互历史下把它具体化。

回放同时保留了早期任务的行为，以及在经验条件下执行历史策略的能力。harness 保留对策略的访问，回放则在模型参数演化的过程中，排练这些策略对上下文的依赖性使用。

我们用单个 LoRA adapter 实现持续参数适配，同时冻结主干参数 W_0。在阶段 t，adapter 从上一学习阶段初始化，而不是独立训练：

    θ_t^init = θ_{t-1}                                (9)

在 B_t 上优化经验条件化目标得到

    W_t = W_0 + ΔW(θ_t)                              (10)

其中 ΔW(θ_t) 表示当前 adapter 诱导的低秩更新。我们既不把 adapter 合并进主干，也不维护不断增长的任务特化 adapter 集合，因此可训练参数预算在整个持续学习过程中保持固定。于是 harness 与模型以不同的方式演化：harness 维护对外可访问的经验，adapter 则持续更新，以改进并保持模型基于这份经验行动的能力。

**可选的 harness 反馈。** 在高质量轨迹被用于模型适配之后，HaMo 可以选择释放相应的记忆条目以回收存储，这实现了图 2 中从模型到 harness 的反馈。该选项在所有报告的实验中都被关闭：所有经验卡跨阶段保持可用。

测试时，初始对话同样由用户请求、初始观测和注入的匹配经验组成。给定 g 和 o^0，harness 从当前记忆中检索经验：

    E = Retrieve((g, o^0), M_t)                        (11)

与锚点选择时用于估计检索覆盖率的完整卡片查询不同，推理时的查询只包含新任务开始时可得的信息。因此它不需要专家轨迹、真实的解法提纲，也不需要未来交互的观测。

检索到的经验提供的是策略级指导，而不是固定的动作序列。在交互步 k，策略按如下方式生成动作：

    a_k ∼ π_{θ_t}(· | g, o^0, h_k, E)                 (12)

其中 h_k 包含当前决策之前累积的观测与动作。随着环境演化，新观测到的状态被纳入 h_k，使模型能把检索到的策略适配到实际执行轨迹上。于是 harness 保留了一条在过往经验中有用的高层策略，而模型决定这条策略在当前对象、条件与可用动作下应当如何实例化。

共享的条件化接口把学习与推理耦合起来：harness 保存可复用的策略，模型学会在上下文中执行它们。保留在记忆中的策略，即便在后续更新削弱了相应行为时，仍能提供显式的线索。

## 4 实验设置

### 4.1 数据集与持续学习协议

我们在三个交互式基准的纯文本环境中评估 HaMo。ScienceWorld [27] 通过需要智能体在环境中导航、操作对象、完成实验的任务来评估科学推理。ALFWorld [19] 在与具身任务对齐的文本环境中提供家务任务，要求智能体找到对象，并执行移动、清洁、加热、冷却等操作。WebShop [30] 评估指令条件化的网购：智能体搜索商品、查看描述、选择选项，并完成满足用户需求的购买。三个基准合起来覆盖科学实验、家务操作与基于网页的决策，动作空间与任务语义各不相同。

我们考虑两种持续学习设置。在域内持续学习中，把 ScienceWorld 训练集划分为四个规模相同、样本级互不相交的子集。每个子集覆盖全部任务类型，因此尽管训练样本不同，各阶段的任务类型覆盖保持不变。我们逐阶段引入一个子集，模拟在固定任务类型集合上的域内数据增量式持续学习，而不是新任务类型的顺序引入。每个阶段结束后，在整个 ScienceWorld 测试集上评估智能体，整个任务流始终使用同一个评估集。

在跨域持续学习中，智能体依次在 ScienceWorld（S）、ALFWorld（A）、WebShop（W）上学习。每个阶段结束后评估迄今遇到的所有领域，从而既能考察对当前领域的适配，也能考察对更早能力的保持。主跨域实验使用 S → A → W 顺序；顺序消融另外考虑 A → W → S 与 W → S → A。

### 4.2 基线

我们以 Qwen3 [23] 作为统一主干：域内设置评估 Qwen3-8B 与 Qwen3-14B；跨域实验以及组件消融、训练顺序消融使用 Qwen3-8B；模型规模消融另外评估 Qwen3-1.7B 与 Qwen3-4B。所有 Qwen3 智能体都关闭思考模式（thinking mode）。

Base 指不加本文所述额外智能体训练与外部 harness 的主干。Base+Harness 在主干上加入外部经验，但保持其参数固定，从而把"仅经由 harness 的适配"分离出来。

我们还在 Qwen3 主干上实例化了两种智能体训练方法作对比。AgentTuning [33] 通过在交互轨迹上做指令微调来培养智能体能力；其原始形式把智能体轨迹与通用指令数据混在一起。ETO [21]（Exploration-Based Trajectory Optimization，基于探索的轨迹优化）用探索收集失败轨迹，构造轨迹偏好对来做策略优化。这些对比考察智能体训练方法在我们的持续学习设置下表现如何。

如第 3 节所述，HaMo 结合持久的策略记忆、以经验为条件的模型适配与历史回放；其模型更新使用单个持续更新的 LoRA adapter，主干冻结。组件消融中，Harness only 对应 Base+Harness，而 Model only 在既无外部 harness 也无历史回放的情况下做顺序参数适配。这一对比检验的是"把外部经验与模型适配协调起来"的贡献。实现设置与框架伪代码分别见附录 A 和 B。

### 4.3 评价指标

我们以各文本环境原生的打分机制作为性能指标。ScienceWorld 报告环境的任务进度分（task-progress score），对完成科学任务的中间进展给分。ALFWorld 报告任务完成分，在各回合上取平均作为成功率。WebShop 报告环境奖励，衡量所购商品满足请求规格的程度，保留部分得分，而不是把结果压缩成二元成败。分数一律以 0–100 呈现，越高越好。每个评估回合最多 50 轮智能体–环境交互；环境提前终止任务时则更早结束。

域内实验中，Average 汇总所报告的四个阶段分数；Base 分数给出固定主干的参照。跨域性能图中，每个子图对应一个已完成的训练阶段，展示被评估领域上的分数。我们通过比较一个领域刚学完时的分数与其后续阶段的分数，来评估保持情况。训练顺序消融还报告三个最终领域分数之和，作为一个描述性汇总。由于各基准的打分语义不同，这个和是对分领域结果的补充，而不是合并的任务成功率。

## 5 结果

### 5.1 主要结果

#### 5.1.1 域内持续学习

图 3 显示，随着新的训练子集陆续到来，HaMo 在完整的 ScienceWorld 测试集上持续改进，两种模型规模皆然。Qwen3-8B 上，其分数从 38.13 升至 60.49，四阶段平均 52.22；Qwen3-14B 上从 38.61 升至 61.15，平均 53.09。按所报告的数值，这两个平均分分别高出 Base+Harness 13.88 分与 12.44 分。最终阶段相对未适配主干的增益，8B 为 22.94 分，14B 为 21.20 分。

优势是在逐阶段累积中显现的，而不是来自一致更强的初始性能。Stage 1 时，HaMo 在两个主干上都略低于 Base+Harness，但从 Stage 2 起领先所有列出的方法。Base+Harness 整个任务流都紧贴主干参照，说明在该设置下仅靠外部经验带来的改进有限。AgentTuning 与 ETO 则随模型规模呈现不同的轨迹：8B 上总体下滑，14B 上在低迷的首阶段之后回升；不过两者的四阶段平均仍低于 HaMo。这些结果支持"同时适配模型与其经验上下文"对在 ScienceWorld 内持续改进的价值；但仅看阶段平均，并不能分离出对各个任务类型的保持情况。

#### 5.1.2 跨域持续学习

图 4 评估 S → A → W 任务流。最终阶段之后，HaMo 在 ScienceWorld 得 52.43、ALFWorld 得 66.79、WebShop 得 59.64，在每个领域上都超过所有列出的基线。相对 Base 分别提升 14.88、22.26、13.96 分；相对每个最终领域分数上最强的非 HaMo 基线，增益为 ScienceWorld 13.02 分、ALFWorld 19.71 分、WebShop 5.16 分。

中间评估揭示了这些增益是如何产生的。HaMo 在第一阶段后 ScienceWorld 得 52.43，学完 ALFWorld 后升至 54.19，学完 WebShop 后又回到 52.43。也就是说，它最终的 ScienceWorld 分数与刚学完 ScienceWorld 时持平，尽管比中间峰值低 1.76 分。它的 ALFWorld 分数在 WebShop 训练后从 70.08 温和回落到 66.79。相比之下，AgentTuning 的 ScienceWorld 分数从 26.24 跌到 3.13，ETO 则从 20.16 跌到 3.20。两种方法在最后的 WebShop 任务上都优于 Base，但在前两个更早的领域上最终低于 Base。由此可见，在该协议下，成功适配最新的领域并不能保证更早能力的保持。

Base+Harness 较好地保持了主干在更早领域上的表现，但它最终的 WebShop 分数 43.42 低于 Base 的 45.68。HaMo 则把更强的新领域能力获取与明显更好的早先领域表现结合在一起，优于那些基于轨迹训练的基线。这一模式与本文预期的互补性是一致的：持久地访问策略，加上持续学习如何执行这些策略。

### 5.2 消融结果

#### 5.2.1 Harness–Model 协作

图 5 比较 HaMo 与只用 harness、只用模型的适配。Harness only 相对 Base 变化较小，而 Model only 显著提升了新学到的任务：第一阶段后在 ScienceWorld 得 53.98，第二阶段后在 ALFWorld 得 73.72。然而，学完 ALFWorld 之后它的 ScienceWorld 分数掉到 22.18，最终收在 24.57，比首阶段下降 29.41 分。HaMo 则在 ScienceWorld 最终得 52.43，高出 Model only 27.86 分，并与自己的首阶段分数持平。

这种保持收益伴随着可测的取舍。Model only 的最终 ALFWorld 分数高于 HaMo（69.34 对 66.79），而 HaMo 在 WebShop 上略好（59.64 对 58.74）。因此，HaMo 并非在每个领域都支配纯参数适配。它在此消融中的主要优势，是获取与保持之间更平衡的取舍，尤其是在最早的领域上。由于 Model only 同时省去了外部 harness 与历史回放，这一对比支持的是完整的 HaMo 设计，而不是单独隔离外部记忆的作用；它无法分别识别锚点选择、回放与经验条件化各自的贡献。

#### 5.2.2 对训练顺序的敏感性

图 6 考察三种循环训练顺序。HaMo 的最终阶段总分在 S → A → W 下为 178.86，A → W → S 下为 188.41，W → S → A 下为 181.94。所有最终领域分数都超过主跨域实验中相应的 Base 参照，尽管其分布取决于训练顺序。在受测的顺序中，A → W → S 的总分最高，而 W → S → A 取得最高的最终 ALFWorld 与 WebShop 分数（74.09 与 60.43）。

## 6 结论

我们提出了 HaMo——一个面向长时程智能体持续学习的 harness–Model 协作框架。HaMo 把持久的策略级记忆与经验条件化的参数适配结合起来，让新获得的程序性知识能够立即复用，同时逐步提升模型解读与执行检索策略的能力。在 ScienceWorld、ALFWorld 与 WebShop 上的实验表明，HaMo 比只用 harness 或只用模型的方法在适配与保持之间取得了更好的平衡，在域内与跨域持续学习下都表现出更强的鲁棒性。

这些结果凸显了协调外部经验积累与内部模型适配的价值，并指出了一条有前景的方向：构建既能从交互中持续学习、又能保持既有能力的长时程智能体。

## 局限性

HaMo 能抵消跨域训练引发的部分遗忘，但无法完全阻止灾难性遗忘。后续适配仍可能降低先前已学领域的表现，而保持的程度取决于领域顺序。因此，当前结果支持的是对遗忘的部分缓解，而非完全免疫。

## 未来工作

**自适应的经验使用。** 一个有用的扩展是学会：何时检索一条策略、何时拒绝一张不合适的卡、以及执行过程中何时刷新指导。这类决策可以把检索置信度、观测到的任务进展，以及对策略前提的显式检查结合起来。这样智能体就能对误导性经验作出反应，而不是把检索相似度当作适用性的充分证据。

**更强的评估与更广的环境。** 对回放、锚点选择、经验条件化与解码温度做受控消融，将澄清它们各自的贡献与相互作用。重复运行与更长的任务流可以评估变异性与持续遗忘，端到端的成本测量则能暴露性能与记忆维护之间的权衡。把框架扩展到多模态智能体与不断变化的网页环境，将进一步检验经验条件化执行能否迁移到当前这些基于文本的基准之外。

## 附录 A 持续适配与推理流程

算法 1 与算法 2 汇总了实验中使用的持续适配与任务执行流程。记号沿用第 3 节。覆盖率在到来的卡片集合内计算。选择锚点会改变训练集合，而所有经验卡都被保留。可选的记忆释放处于关闭状态，因此在伪代码中省略。回放采样器与拐点检测器以子程序形式表示。

```
Algorithm 1 HaMo: Continual Adaptation
Require: Stage datasets D_1, ..., D_T; frozen backbone W_0;
         initial adapter θ_0
Ensure: Persistent memory M_T and adapter θ_T
 1: M_0 ← ∅; H_0 ← ∅                    ⊲ Historical trajectories
 2: for t = 1, ..., T do
 3:   C_t ← {(g_i, o_i^0, Distill(τ_i)) : τ_i ∈ D_t}
 4:   M_t ← M_{t-1} ∪ C_t
 5:   for each card i ∈ C_t do
 6:     N3(i) ← Top3(i, C_t \ {i})
 7:   end for
 8:   R_j ← {i : j ∈ N3(i)} for each j ∈ C_t
 9:   S ← [ ]; U ← ∅; q ← [0]
10:   while an unselected candidate remains do
11:     j* ← arg max_{j∉S} |R_j \ U|
12:     if |R_j* \ U| = 0 then
13:       break
14:     end if
15:     Append j* to S; U ← U ∪ R_j*
16:     Append |U| to q                   ⊲ Coverage curve
17:   end while
18:   N_t* ← KneePoint(q)
19:   A_t ← {SourceTrajectory(S[m]) : 1 ≤ m ≤ N_t*}
20:   B_t^old ← SampleReplay(H_{t-1})
21:   B_t ← A_t ∪ B_t^old
22:   for each τ_i ∈ B_t do
23:     E_i ← RetrieveOrMatch(τ_i, M_t)
24:     Pair expert actions with (g_i, o_i^0, h_{i,k}, E_i)
25:   end for
26:   θ_t ← θ_{t-1}
27:   Train θ_t on L_t for 3 epochs, learning rate 2 × 10^{-4}
28:   Keep W_0 frozen; retain the same LoRA adapter
29:   H_t ← H_{t-1} ∪ D_t
30: end for
```

算法 1 中的贪心选择是为清晰起见而写成显式形式的；实现使用惰性优先队列更新，以得到同样的边际覆盖选择。历史集合 H_t 指的是可用于回放的样本池，而不是另一个可训练模型。在第一阶段，回放集合为空。训练损失是 3.2 节中的经验条件化行为克隆目标。

```
Algorithm 2 HaMo: Experience-Conditioned Inference
Require: Task g, initial observation o^0, memory M_t, adapter θ_t,
         frozen backbone W_0
 1: E ← Retrieve((g, o^0), M_t)
 2: Construct initial dialogue from (g, o^0, E); set h_0 ← [o^0]
 3: for k = 0, ..., 49 do
 4:   Sample a_k ∼ π_{θ_t}(· | g, o^0, h_k, E)
       using decoding temperature 0.7
 5:   (o_{k+1}, r_k, d_k) ← EnvironmentStep(a_k)
 6:   h_{k+1} ← h_k ∥ (a_k, o_{k+1})
 7:   if d_k indicates termination then
 8:     break
 9:   end if
10: end for
11: return Recorded trajectory and environment score
```

推理查询只用任务与初始观测。检索到的仍然只是指导：后续动作还依赖不断演化的交互历史。构造推理查询不需要专家解法，也不需要未来观测。

## 附录 B 实现与实验设置

实验使用显存 80 GB 的 NVIDIA A800 GPU。在每个适配阶段，我们把被选中的锚点轨迹连同历史回放训练 3 个 epoch，学习率为 2 × 10⁻⁴。只更新 LoRA adapter，秩 r = 16，缩放参数 α = 32；主干保持冻结。同一个 adapter 跨阶段延续，而不是重新初始化或换成任务特化的 adapter。表 2 汇总了这些设置。

表 2：HaMo 的实现与评估设置。

| 设置 | 值 |
|---|---|
| GPU 硬件 | NVIDIA A800, 80 GB |
| 每阶段训练 epoch 数 | 3 |

**随机化的智能体推理。** 我们把推理温度设为 0.7，以便在基于轨迹的训练之后保留动作生成的多样性。交互任务可能要求智能体在当前状态与检索到的例子不一致时调整决策；采样旨在减少过于确定的执行模式，并允许出现替代动作。这是一个解码层面的选择，不是训练正则化，也不构成对过拟合的保证。我们没有把报告的增益特别归因于温度，因为文中并未包含温度消融。

**评估协议。** 每个回合在环境终止或 50 轮交互之后结束。我们使用原生任务分数并以 0–100 报告，ScienceWorld 与 WebShop 保留部分得分。域内协议使用四个样本级互不相交的 ScienceWorld 训练阶段，每阶段之后评估完整测试集。跨域评估遵循第 4 节所述的任务顺序，测量在迄今遇到的领域上的表现。
