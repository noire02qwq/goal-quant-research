## 摘要（Abstract）

记忆可能对当下的推理而言已经过时，却是重建过去所不可或缺的。基于相关性的检索忽视了这一张力：语义相关性（semantic relevance）、以证据为依据的有效性（evidence-grounded validity）与针对具体查询的资格（query-specific eligibility）是三个彼此独立的概念。我们提出 CALM——一个冲突感知的生命周期记忆治理框架，它把持久记忆的保存与查询时的准入解耦开来。CALM 将异构记录转换为以证据为依据的记忆单元（memory cell），利用支持（support）、冲突（conflict）与依赖（dependency）信号更新有效性和生命周期状态，并通过考虑时间适用性的免训练门控或可学习门控，准入与当前查询相匹配的证据。在 LongMemEval-S 与 LoCoMo 上、分别以 Qwen 与 GPT 为骨干模型时，CALM 优于当前最好的基线，取得最佳的总体准确率。与简单的过滤和重排序相比，查询条件化的准入能进一步改善证据选择。冲突阻断与鲁棒性分析表明，CALM 在抑制被错误检索的记忆的同时保留了有用证据。历史重建实验证明：保留被取代的记录，可以在不损害当前状态回答的前提下支撑准确的早期状态推理。

## 1 引言

对长程语言智能体来说，可靠的记忆不仅要求决定**保留什么**，还要求决定**使用什么**。随着用户搬迁、修改偏好或改变约定，交互历史中不断累积的记录虽然仍能说明过去，却可能不再描述现在。现有的记忆增强系统已经在这些历史的存储、组织与检索上取得了进展（Packer et al., 2023; Zhong et al., 2024; Gutierrez et al., 2024; Rasmussen et al., 2025）。然而，语义相关并不意味着具备查询资格：一条被检索到的记忆可能在主题上与问题相关，却对所询问的状态既不可靠也不适用（Shi et al., 2026; Liang et al., 2025）。这种错配会把一次成功的检索变成误导性的推理。

考虑一位从西雅图搬到波士顿的用户。早先的住址不应当决定一个「当前所在地」查询的答案，但对于「你之前住在哪里」这样的问题仍然必不可少。如图1所示，删掉较早的记录会丢失历史证据，而不加区分地把两条记录都放进来又会掩盖当前状态。这个例子暴露出记忆的三个不同属性：**语义相关性**衡量与查询的关联程度；**与查询无关的有效性**反映记忆持久的、由证据支撑的状态；**查询条件化的资格**则依据查询的时间目标、适用范围与意图，决定它是否应当进入工作上下文。即便是一条已被取代的记忆，也可能有资格参与历史重建；而另一条证据充分的记忆，只要时间或范围与查询不匹配，就仍然可能没有资格。

基于图结构和时序的记忆系统能够表示不断演化的关系，近期工作还进一步凸显了冲突记录带来的挑战（Gutierrez et al., 2024; Xu et al., 2025; Rasmussen et al., 2025; Tao et al., 2026）。但记录下一次更新或一次冲突，本身并不能回答「针对某个具体问题应当准入哪些检索记录」。记忆使用策略必须同时考虑持久证据和查询施加的条件。这要求把生命周期治理与查询条件化的准入分开，而不是只依赖记忆组织或基于相关性的排序。

我们提出**冲突感知生命周期记忆治理**（Conflict-Aware Lifecycle Memory Governance，CALM），这是一个把持久生命周期治理与查询条件化准入分开的两层框架。CALM 位于记忆后端与工作上下文之间，把异构记录改造成以证据为依据的单元，同时保留来源与时间信息；它用确定性的支持、冲突与依赖规则更新存储的有效性和生命周期状态，由时间线索引导适用性判断，而不是自动衰减。在查询时，先经过一个共享的硬性资格过滤器，之后进入免训练策略（CALM-ZS）或可学习门控（CALM）。两者都依据检索相关性、存储的有效性、查询—记忆兼容性以及查询条件化的风险来选择证据。这样，CALM 为历史查询保留被取代的记录，同时把它们排除在当前状态推理之外，且不需要修改底层检索器或回答模型。

我们在 LongMemEval-S（Wu et al., 2025）与 LoCoMo（Maharana et al., 2024）上、跨 Qwen 与 GPT 骨干评估了 CALM。CALM 在所有被评测的设置中取得最好或并列最好的总体准确率，在 LongMemEval-S 上配合 Qwen3-30B-A3B-Instruct-2507 达到 79.60%。与简单过滤、重排序的对照比较，展示了把生命周期治理与查询条件化准入结合起来的好处。冲突阻断与鲁棒性分析表明，CALM 既抑制误导性证据，又保留有用记忆；历史重建则确认被取代的信息依然可访问，同时不损害当前状态推理。组件消融与效率分析进一步凸显了持久治理与查询感知选择之间的互补作用。

我们的贡献如下：

- 我们把长程记忆的使用形式化为一个**查询条件化的资格问题**，在保留历史证据的同时，区分语义相关性、与查询无关的有效性以及针对具体查询的准入。
- 我们提出 CALM，它把以证据为依据的生命周期治理与基于兼容性和风险的准入耦合在一起，并同时实现了免训练与可学习两种门控策略。
- 我们在两个基准、三种回答模型骨干上验证了 CALM：既与现有记忆系统及简单替代方案对比，也做了鲁棒性、历史重建与效率分析。

## 2 相关工作

### 2.1 面向 LLM 智能体的长期记忆

长期记忆让 LLM 智能体得以保留交互历史、个性化回答，并支撑跨会话的规划与推理。早期智能体保留观察、反馈和习得的技能来支持跨会话规划（Park et al., 2023; Shinn et al., 2023; Wang et al., 2024）。MemoryBank（Zhong et al., 2024）维护用户信息，MemGPT（Packer et al., 2023）则在分层记忆层级之间换页调度上下文；外部记忆架构进一步扩展了召回规模（Wang et al., 2023）。但仅有持续检索，并不能保证过去的证据对当前查询仍然有效或适用。

### 2.2 结构化记忆系统

近期系统通过相互链接的笔记、图和层级来组织记忆（Anokhin et al., 2025; Sun et al., 2026; Nan et al., 2025）。HippoRAG（Gutierrez et al., 2024）把知识图与 Personalized PageRank 结合，实现联想式的多跳检索；A-Mem（Xu et al., 2025）动态地链接并演化记忆笔记。Mem0（Chhikara et al., 2025）通过增加、更新与删除操作整合对话事实。MemoryOS、MemOS 与 EverMemOS（Kang et al., 2025; Li et al., 2025; Hu et al., 2026）探索分层管理与记忆生命周期。HippoRAG 侧重联想检索，A-Mem 关注自适应的记忆组织，Mem0 处理增量记忆更新，而 CALM 聚焦于**检索之后的资格控制**。

### 2.3 时间一致性与记忆治理

已有工作研究记忆的过期、冲突与干扰（Chao et al., 2026; Tao et al., 2026; Shi et al., 2026; Lam et al., 2026; Hu et al., 2025; Lin et al., 2026; Dash et al., 2026）。Zep（Rasmussen et al., 2025）用双时态图追踪被取代的事实，Mem0（Chhikara et al., 2025）通过记忆更新来消解冲突。A-TMA（Shi et al., 2026）则协调记忆库维护、状态感知的证据扩展以及回答时的冲突消解。相比之下，CALM 针对的是**检索之后的准入**：它先维护以证据为依据、与查询无关的有效性与生命周期状态（其中包括依赖失效），再对已经固定的检索候选施加硬性资格约束和免训练或可学习的门控。与 A-TMA 的证据扩展和回答侧状态消解不同，CALM 明确治理哪些既有记忆可以进入工作上下文，而不改动上游检索或回答模型。

## 3 CALM 架构

**问题设定。** 一个长程语言智能体累积交互历史

```
H_t = {(x_ℓ, y_ℓ, τ_ℓ)}  ℓ = 1..t
```

其中 x_ℓ、y_ℓ、τ_ℓ 分别表示第 ℓ 步的用户输入、智能体回复与时间戳。既有的记忆后端把这段历史转换为持久记录 M̃_t，CALM 再将其适配为规范化记忆单元集合 M_t。给定查询 q，上游检索器提供候选记忆，适配之后记作 R_q ⊆ M_t。对于每条被检索的记忆 m_i^t ∈ R_q，我们区分三个性质：语义相关性 ζ_{q,i}^t ∈ [0,1] 衡量它与查询的关联程度；与查询无关的有效性 V_i^t ∈ [0,1] 反映基于累积证据的可靠程度；查询条件化的资格 g_{q,i}^t ∈ {0,1} 则决定在查询的时间目标、适用范围与意图之下它是否应当被准入。三者互不等价：一条相关的记忆可能已被取代或被驳斥，而一条被取代的记忆对历史查询却仍可能有资格。据此，工作上下文定义为

```
C_q = {m_i^t ∈ R_q | g_{q,i}^t = 1}
```

智能体据此生成答案 â = f_LLM(q, C_q)。

**框架概述。** 受人类记忆自适应生命周期的启发（Atkinson and Shiffrin, 1968; Nader et al., 2000; Hupbach et al., 2007），我们提出 CALM——一个把持久记忆保存与查询时利用分开的冲突感知生命周期记忆治理框架。如图2所示，CALM 包含三个阶段：**Evidence-Grounded Memory Adaptation（以证据为依据的记忆适配）**把异构后端记录转换为规范化记忆单元；**Lifecycle-Aware Memory Governance（生命周期感知的记忆治理）**通过支持、冲突、依赖与时间信号维护以证据为依据的有效性和生命周期状态；**Query-Conditioned Memory Gating（查询条件化的记忆门控）**则用免训练的 CALM-ZS 规则或可学习的 CALM 策略挑选合格记忆。CALM 并不替换底层的存储或检索架构，而是把持久的生命周期治理与查询局部的准入决策分开，让被取代的记忆可以继续用于历史重建，却不会自动进入当前状态推理。

### 3.1 阶段 I：以证据为依据的记忆适配（Evidence-Grounded Memory Adaptation）

记忆后端把交互历史表示为对话片段、抽取事实、摘要或结构化记录，它们的粒度与元数据各不相同。为了实现一致的记忆治理，CALM 在保留原始证据来源的前提下，把这些异构后端记录转换为规范化记忆单元：

```
m_i^t = (c_i, E_i^t, a_i, ρ_i^t, s_i^t),
a_i  = (κ_i, τ_i, π_i, U_i, Ω_i).                     (1)
```

这里 c_i 是记忆单元的规范化内容，具体可能对应一个抽取出来的命题，也可能是一段保留的原文片段，取决于后端记录可用的结构。属性元组 a_i 指定语义类型 κ_i、时间锚点 τ_i、来源出处 π_i、关联实体 U_i 与适用范围 Ω_i。聚合可靠性权重 ρ_i^t ∈ [0,1] 概括各证据来源的相对贡献，s_i^t 则表示记忆的生命周期状态。

因此，适配层是异构记忆存储与生命周期治理之间的接口：它保留证据的可追溯性，同时暴露后续有效性估计与冲突感知推理所需的结构信息。新建的单元初始化为 CANDIDATE（候选），其有效性与生命周期状态由后续基于证据的治理来更新。这个过程保留了可追溯的证据，既不提前消解冲突，也不做任何针对具体查询的准入决策。详细的适配规则、证据对齐方式与来源可靠性权重见附录 A.1。这些操作既建立起下游生命周期治理所需的证据结构，又保留了原始后端信息。

### 3.2 阶段 II：生命周期感知的记忆治理（Lifecycle-Aware Memory Governance）

经过阶段 I 之后，CALM 已保留证据出处，并通过一张**生命周期图**把不断演化中的主张链接起来。规范化后完全相同的主张会在记忆单元层面合并，其证据计数随之更新；当前实现并不为「支持」关系单独打分。冲突与依赖链接由确定性规则识别：

```
G_t  = (M_t, E_conf^t, E_dep^t),
p_ij^{r,t} = f_r(m_i^t, m_j^t),   r ∈ {conf, dep}      (2)
```

检出的对立主张会保留冲突链接。强度不低于 0.75 的非弱冲突可以触发取代（supersession）；更弱的冲突只做记录，不自动替换任何一方。依赖边 (j, i) 从来源或前置记忆 m_j 指向依赖它的记忆 m_i。只要相应规则命中就会创建依赖链接，不再附加全局边阈值。完整的规则赋值见附录 A.3。

CALM 利用保留的证据与生命周期事件，追踪累积支持度 S_i^t、冲突风险 C_i^t 与依赖失效风险 D_i^t。在附录 A.3 描述的实现中，这些量用于支撑治理决策，并不被送入一个另行重算的 sigmoid 有效性分数。相反，记忆的有效性作为一项**存储的可操作属性**，与持久的生命周期状态并列维护：

```
(V_i^t, s_i^t) = U_life(V_i^{t-1}, s_i^{t-1},
                        ΔE_i^t, ΔE_conf^t, ΔE_dep^t)   (3)
```

这里的 U_life 表示确定性的生命周期与存储有效性更新，不是一个可学习的打分函数。直接的用户证据或不低于 0.60 的置信度可以激活（ACTIVE）一个候选；重复的支持或不低于 0.80 的置信度则可把它晋升为 STABLE（稳定）。强取代会把被替换记忆的存储有效性封顶在 0.15。时间信息用于确定更新的先后顺序与适用区间；**仅仅时间流逝本身不会触发 STALE 转移**。依赖失效可以触发核验，或使依赖方记忆变为 STALE（过时），而归档则由一个可选的保留策略管理。这些持久性更新不同于阶段 III 的查询时资格决策，细节见附录 A.3。

### 3.3 阶段 III：查询条件化的记忆门控（Query-Conditioned Memory Gating）

与查询无关的有效性并不能保证对某个具体查询的资格。一条有效的记忆可能落在查询的时间范围或适用条件之外，而一条被取代的记忆对历史查询却可能依然有用。因此，CALM 对被检索的记忆做查询时准入治理，而不是只依赖语义相关性。

对查询 q，记 R_q ⊆ M_t 为上游检索器给出的候选集。对每条被检索的记忆 m_i^t ∈ R_q，CALM 构造四维表示

```
x_{q,i}^t = ( ζ_{q,i}^t , V_i^t , ψ_{q,i}^t , 1 − R_{q,i}^t )   (4)
```

其中 ζ_{q,i}^t 是语义相关性，V_i^t 是阶段 II 估计的与查询无关的有效性，ψ_{q,i}^t 度量查询—记忆兼容性，R_{q,i}^t 汇总查询条件化的冲突、依赖、时间与生命周期风险。

CALM 对同一组特征施加两种策略之一——固定的免训练策略（CALM-ZS）或可学习策略（CALM）：

```
F_b(x_{q,i}^t) = { w_zs^⊤ x_{q,i}^t,                  b = zs,
                  σ( f_φ(x_{q,i}^t) ),                b = learn   (5)
```

其中 w_zs = (1/4, 1/4, 1/4, 1/4)^⊤ 是固定权重，f_φ 只在开发集实例上训练，训练用的查询—记忆监督是独立构造的。

两种策略都先施加同一个硬性资格过滤器 h_{q,i}^t ∈ {0,1}（定义见附录 A.4），最终的二元准入决策为

```
g_{q,i}^{b,t} = h_{q,i}^t · I( F_b(x_{q,i}^t) ≥ θ_b )          (6)
```

其中 θ_zs 是固定的 CALM-ZS 阈值，θ_learn = 0.50 是可学习门控的阈值。它们的取值与实现细节见附录 A.4。工作上下文为

```
C_q^{b,t} = { m_i^t ∈ R_q | g_{q,i}^{b,t} = 1 }.                (7)
```

被准入的记忆按其策略分数排序，并在同一个记忆 token 预算下装填。被拒绝的记忆仍留在持久存储中，可以继续支持兼容的历史查询。

## 5 结论

可靠的长程记忆不只是「留住信息」，还要决定**保存下来的证据何时应当参与回答**。我们提出了 CALM：一个把「以证据为依据、与查询无关的生命周期治理」与「对检索记忆的查询条件化准入」分离开来的框架。CALM 既保留来源出处与被取代的状态，又通过查询兼容性与风险来控制准入，从而在不损害当前状态推理的同时支持历史重建。在 LongMemEval-S 与 LoCoMo 上、跨 Qwen 与 GPT 骨干的实验取得了最好的总体准确率。冲突阻断、历史重建，以及与简单过滤／重排序策略的对比，进一步证明了「在语义相关性之外治理记忆使用」的价值。未来工作将探索动态、多模态环境下可扩展的生命周期维护。

## 局限性（Limitations）

CALM 有几点局限。第一，它的生命周期治理依赖确定性规则与可得的证据元数据，可能遗漏隐式的或复杂的冲突。第二，查询条件化的门控依赖上游检索质量，偶尔会排除有用证据，在多跳推理上尤其如此。第三，学习式门控需要开发集监督，它向未见领域的泛化仍有待探索。第四，我们的评测仅限于 LongMemEval-S 与 LoCoMo 的非对抗子集。生命周期图维护在更大、持续演化的记忆环境中的可扩展性也值得进一步研究。

### A.1 阶段 I：以证据为依据的记忆适配

**输入记录与适配粒度。** 适配器处理既有记忆后端暴露的记录，并保留其原始内容与来源出处；结构化属性在可用时映射到相应的单元字段。

对于文本记录，确定性规则会抽取显式事实或有边界的片段；当无法可靠切分时，就保留原始片段或对话轮次作为一个单元。因此，**记忆单元是证据与生命周期管理的单位，但不必然是一条原子命题**。我们的实现采用确定性的适配规则以保证可复现，而表示本身与后端无关，也不依赖任何特定的抽取模型。

在 LongMemEval-S 上，原始消息按标点感知的边界切分为不超过 900 字符的片段，每条消息至多保留 12 个片段；覆盖显式更新、时间陈述、偏好与跨会话线索的规则派生片段上限为 220 字符。会话锚点还会保留每个会话的前三条消息。对每道评测题，记忆构建只使用问题日期当天及之前可得的会话，防止未来信息泄漏。

在 LoCoMo 上，每个带时间戳的对话轮次都被保留为来源级单元。数据集自带的观察、事件摘要与会话摘要被作为额外的证据表示纳入。这些记录对所有 CALM 变体都可用，且不被用作答案监督、门控标签或参考信息——它们由基准提供，而不是由被评测的模型生成。由于多种表示可能描述同一段对话，它们被视为同一证据的不同视图，而非相互独立的佐证。

单元属性与缺失信息方面：属性 κ_i 记录后端给出的语义类别或规则匹配到的类别（例如偏好、资料属性、事件、约束或时间事实）。实体 U_i 与适用范围 Ω_i 只从可用的结构化字段或显式文本线索填充。来源出处 π_i 存储记录类型与原始交互标识。时间锚点 τ_i 表示可用的观察时间戳，而显式声明的事件时间另行存储。缺失的属性留空而不做推断。这些字段描述的是证据属性，并不直接决定记忆的有效性。

证据模式与来源方面：每个记忆单元遵循式 (1)，其证据集合包含如下条目：

```
e = (id, u, τ, π, r, ν)                               (8)
```

在字段可用时映射到相应的单元字段。其中 id 标识证据条目，u 是原始来源内容，τ 是观察时间戳，π 存储来源类型、会话、轮次与说话人身份等出处信息，r 区分直接观察到的记录与派生表示，ν ∈ [0,1] 是赋予的来源可靠性权重。说话人身份与证据来源保持分离：例如，LoCoMo 的某位参与者不会仅仅因为其说话人标签与「用户」不同，就被当作助手给出的推断。显式事件时间也与观察时间戳区分开来。

证据对齐与可靠性方面：为识别完全重复的记录，我们对来源文本做小写化、边界裁剪与重复空白折叠等规范化。规范化键相同的记录共享同一个记忆单元，其证据集合按唯一证据标识合并，同时保留原始来源。语义相似的记录不会仅凭相似度就合并；实体与属性相同但取值不同的记录保持分离，以便生命周期治理判断它们是冲突，还是不同的时间状态。

我们按证据来源与粒度赋予固定的来源可靠性权重 ν，如表7所示。这些权重表示证据聚合时的相对贡献，而不是经过校准的事实正确性概率。局部化的观察与显式片段比宽泛的摘要权重更高，因为它们提供的证据更直接。权重在不同数据集与模型之间保持固定，也不在评测实例上调参。为考察这一设计选择的敏感性，我们在附录 A.2 中比较了替代的加权策略。当多条证据条目对齐时，记忆单元的聚合来源可靠性按下式计算：

```
ρ_i^t = max_{e ∈ E_i^t} ν(e)                          (9)
```

阶段 II 会独立地聚合累积证据与关系信号，以估计与查询无关的有效性 V_i^t。因此，ρ_i^t 只表示来源级的证据加权，不应被解读为有效性的概率。新建的单元初始化为 CANDIDATE，后续的晋升与生命周期转移由阶段 II 决定，而不是由适配过程本身决定。

### A.2 来源可靠性权重的敏感性

表7中的来源可靠性权重提供了一种基于来源出处与粒度的轻量证据聚合机制。为了检验 CALM 是否依赖这一特定加权方案，我们在保持其余组件不变的前提下比较三种变体：

- **Source-specific**：默认设置，使用表7中的权重。
- **Uniform**：所有证据来源取同一权重 ν = 0.75。
- **No weighting**：取消来源区分，所有证据条目一律 ν = 1。

结果显示，CALM 在替代加权策略下依然有效，而默认的按来源加权取得最好成绩。这说明 CALM 的提升并不依赖某一套特定的人工赋权配置，主要收益来自**以证据为依据的生命周期治理**与**查询条件化的记忆准入**。

### A.3 阶段 II：生命周期感知的记忆治理

**关系识别。** 阶段 I 之后，CALM 在规范化记忆单元之上构建一张生命周期图，用来表示支撑性证据、相互冲突的主张以及记忆之间的依赖。沿用正文式 (2) 的关系形式化，关系识别通过确定性规则实现，依据是证据出处、结构化属性、时间信息与词汇重叠。这里不使用外部 LLM 裁判，也不使用可学习的成对关系分类器。由此得到的置信度表示**操作层面的关系强度**，而不是经过校准的概率。

三类关系的实现方式各不相同。「支持」通过完全重复合并来处理，而不是单独打分的图边：两条记忆记录在小写化、裁剪与空白规范化之后内容一致就合并，其证据记录、来源轮次标识与置信度信息随之保留或更新。因此实现中并不需要单独的支持边阈值 θ_sup。

对于冲突与依赖关系，检出的配对会获得规则特定的强度：

```
p_ij^{r,t} = f_r(m_i^t, m_j^t),   r ∈ {conf, dep}      (10)
```

操作规则与判定准则汇总在表9。

**冲突识别** 先用相容的实体—属性槽位或相关的个人主张把候选配对限制在一个小范围内，然后按顺序应用规则：偏好反转、约束变化、时间性位置更新、任务状态变化、结构化槽位更新，以及更弱的对立信号。它们的置信度按关系类型固定取值（见表9）。所有检出的冲突都会保留，但只有 p_conf ≥ 0.75 的非弱冲突才触发取代。因此 **0.75 是「强冲突」的判定阈值，而不是记录冲突关系的最低门槛**。冲突链接双向存储，以便后续检索与一致性检查保留这条关系。

**依赖链接** 沿证据传播方向建立：边 (j, i) 表示记忆 m_j 是 m_i 的来源或相关前提。显式的来源记忆引用获得最高置信度；更弱的关联则由共享结构化属性、对话轮次出处、预定义语义线索或规范化词元重叠决定。重叠分数定义为

```
o_ij = |T_i ∩ T_j| / sqrt(|T_i| · |T_j|)              (11)
```

其中 T_i、T_j 分别是两条记忆的内容词元集合。只要相应规则条件满足就创建依赖链接，不再施加全局阈值 θ_dep；依赖强度随后用于失效风险的传播。需要强调的是，**仅凭语义相似并不足以在不同主张之间建立等价关系**：非重复的记忆仍是彼此独立的记录，生命周期图由此保留相互冲突的陈述、时间上的更新以及各自独立支撑的信息。

**信号聚合。** CALM 为每条记忆维护三个治理信号：累积支持度 S_i、冲突风险 C_i 与依赖失效风险 D_i。它们由存储的证据、检出的关系与生命周期事件导出，不使用评测问题或其参考答案。

支持信号综合累积证据与证据置信度：

```
S_i = min( 1 , 0.55 · min(1, n_i / 3) + 0.45 · c̄_i )  (12)
```

其中 n_i 是有效证据数，取「存储的支持计数」与「保留的证据记录数」中的较大者；c̄_i 是保留证据记录的平均置信度，若没有证据记录则使用记忆本身的置信度。证据数量的贡献在 3 条之后饱和，避免反复出现的观察把支持度推到无界。

冲突风险由最强的保留冲突决定：

```
         ┌ 0,                                  L_i^conf = ∅
C_i =    │ 1,                                  s_i = SUPERSEDED
         └ max_{ℓ ∈ L_i^conf} conf(ℓ),         其他情况            (13)
```

其中 L_i^conf 是保留的冲突链接集合，conf(ℓ) 是相应规则赋予的置信度。带保留冲突的被取代记忆取得最大冲突惩罚，而较弱的冲突仍可供下游一致性控制使用，不一定导致取代。

**依赖失效风险**在来源记忆被取代时更新。对每条受影响的记忆 m_i 与其被取代的来源 m_j，更新为

```
D_i^{(k+1)} = min(1, D_i^{(k)} + 0.4 · d_{ji}),   D_i^{(0)} = 0   (14)
```

其中 d_{ji} 是存储的依赖强度，k 索引各次不同的传播性失效事件。每个被取代的来源对同一条依赖记忆至多贡献一次（由被传播来源的标识符追踪）。若一条依赖只通过证据引用建立、没有打分的依赖链接，实现中使用 0.40 的回退强度。

依赖失效的后果由两条不同的准则决定：其一，当累积的级联风险满足 D_i ≥ 0.70 时，该记忆被标记为待核验；其二，当被取代的来源与之存在 d_{ji} ≥ 0.80 的强依赖时，受影响的记忆转入 STALE 并同样被标记待核验。**这些阈值控制的是核验与生命周期转移，而不是初始依赖边的构建。**

**生命周期转移规则。** 每条新建的记忆在证据评估之前先进入 CANDIDATE（候选）状态。实现采用显式的转移条件，而不是估计状态转移概率。

CANDIDATE 只要在保留的证据中至少有一条是用户直接陈述的、或记忆置信度不低于 0.60，就转为 ACTIVE（活跃）。ACTIVE 记忆在有效证据数达到 2 条或置信度不低于 0.80 时晋升为 STABLE（稳定）。这些条件是**按顺序评估**的，因此证据足够充分的候选可以在同一轮更新中直接到达 STABLE。

当新进入的记忆与既有记录形成强冲突时，新记忆被赋为 ACTIVE，与之冲突的旧记录转为 SUPERSEDED（被取代）。旧记录保留一个指向替换记忆的指针，其有效性结束时间按新记忆的有效性起始时间或时间戳更新，存储有效性分数被封顶在 0.15。弱冲突只做记录，不自动替换任何一条记忆。

STALE（过时）状态表示其持续适用性已被失效的上游证据破坏的记忆：当它对某个被取代来源存在 d_{ji} ≥ 0.80 的强依赖时触发该转移。生命周期管理器也支持对 ACTIVE、STABLE 或已合并（consolidated）的记忆做显式的「上游被取代」转移。时间信息参与冲突识别与有效性区间的确定，但**核心生命周期更新器不会仅仅因为时间流逝，就把一条本身没有被驳斥的记忆标记为过时**。

归档由一个独立的、可选启用的保留策略处理：在该策略下，一条 STALE 或 SUPERSEDED 记忆只有在「无记录访问、效用低于 0.45、新鲜度不超过 0.35」时才被归档。当配置的活跃记忆预算超限时，基于容量的保留还可能额外归档或压缩排名靠后的记忆。这些归档操作仅在相应保留策略启用时才生效。

**存储有效性与状态转移。** 实现中的生命周期管理器把有效性属性 V_i ∈ [0,1] 与证据置信度、支持计数、冲突链接、级联风险分开存储。此处使用的阶段 II 实现并不通过四个信号的 sigmoid 聚合来重算 V_i，而是由规则触发的生命周期操作来更新持久状态与存储有效性：候选由直接用户证据或置信度 ≥ 0.60 激活；活跃记忆在至少两条有效证据或置信度 ≥ 0.80 之后转为稳定。激活与晋升会强制存储有效性不低于 0.65，而强取代会把被替换记录的存储有效性封顶在 0.15。这些操作对应正文的式 (3)；证据、冲突与依赖风险则继续作为独立的回想信号可用。

一条 STALE 或 SUPERSEDED 记忆只有在可选保留策略启用时、且满足上述归档条件，才可能被归档。在历史回想中，一条兼容的历史记录可以在**查询局部的副本**中被重新激活，而不改变持久状态。任何后端特定的合并或再激活操作，都必须与正文列出的六个生命周期状态区分开。这些操作不假设任何经过校准的概率，也不使用可学习的成对关系模型。

**表9：CALM 实现中的操作化关系构建与判定准则。**

| 关系 | 考虑的证据 | 操作化打分规则 | 判定准则 |
|---|---|---|---|
| Support（支持） | 小写化与空白规范化后的完全匹配；累积证据与来源置信度。 | 规范化后完全相同的记录被合并，证据计数与置信度随之更新；不计算独立的支持边分数 f_sup。 | 规范化后精确匹配即可；无 θ_sup。 |
| Conflict（冲突） | 相匹配的实体—属性槽位或相容的个人主张；偏好极性、约束、位置变化与任务状态。 | f_conf = 0.95（偏好反转）、0.94（时间性位置变化）、0.92（约束变化）、0.90（任务状态变化）、0.88（槽位值更新），或 0.70（重叠 o ≥ 0.45 的弱对立信号）。 | 所有检出的冲突都建立链接。强冲突：f_conf ≥ 0.75 且非弱类型。 |
| Dependency（依赖） | 显式来源记忆 ID、共享结构化槽位、对话轮次出处、预定义语义线索与词元重叠。 | f_dep = 0.95（显式引用）；0.55（同槽位、非派生）；max(0.90, o)（派生、同轮次、o ≥ 0.12）；max(0.80, o, s)（派生、语义线索 s ≥ 0.75）；或 0.70（派生、主题重叠 o ≥ 0.45）。 | 规则命中即建链；无全局 θ_dep。级联风险 D_i ≥ 0.70 时核验；被取代来源且 f_dep ≥ 0.80 时标记为 stale。 |

> 注：词元重叠 o = |T_i ∩ T_j| / √(|T_i|·|T_j|)，其中 T_i 表示记忆内容词元集合。语义关联分数 s 由预定义匹配规则确定。候选记忆凭直接用户证据或置信度 ≥ 0.60 转为 active，active 记忆凭至少两条证据或置信度 ≥ 0.80 转为 stable。这些是生命周期准则，而非支持边阈值。

### A.4 阶段 III：查询条件化的记忆门控

**硬性资格过滤。** 上游检索器首先给出 R_q；CALM 不额外增加一次检索。CALM-ZS 与可学习的 CALM 使用同一个基于规则的硬过滤器 h_{q,i} ∈ {0,1}。对**当前状态查询**，处于 CANDIDATE、ARCHIVED、STALE 或 SUPERSEDED 状态的记录通常被排除，后端显式屏蔽的记录同样排除。对**显式的历史查询**，较早的 STALE、SUPERSEDED 或 ARCHIVED 记录若其保留的有效性区间与内容匹配目标历史状态、且实现暴露了一个合格的查询局部副本，则可以被准入；这种准入不改变持久状态。

依赖核验标志（例如阶段 II 中 D_i ≥ 0.70 的触发）与显式的拒绝决策是两回事：只有当配置的资格规则把该记忆标记为 blocked 时，它才会导致硬性排除。一旦 h_{q,i} = 1，后续就施加同一套四维特征构造与各分支对应的 0.50 准入阈值。

**兼容性与查询条件化风险。** 对通过硬过滤器的每条记忆，CALM 由四个归一化因子计算查询—记忆兼容性：

```
ψ_{q,i} = (1/4)( ψ^time_{q,i} + ψ^entity_{q,i}
               + ψ^scope_{q,i} + ψ^type_{q,i} )              (15)
```

每个因子都落在 [0,1]。time 因子检查记忆声明的时间或有效性区间是否匹配查询目标；entity 与 scope 因子评估实体同一性与适用性约束；type 因子衡量记忆语义类型与查询意图之间的兼容程度。

查询条件化风险分数聚合四个归一化风险分量：

```
R_{q,i} = (1 − (1 − r^dep_{q,i})(1 − r^conf_{q,i}))
          · (1 − r^time_{q,i})(1 − r^life_{q,i})              (16)
```

它们分别表示查询特有的冲突风险、依赖失效风险、时间错配风险与生命周期不相容风险。对历史查询，匹配的历史区间会相应降低时间与生命周期惩罚。兼容性分数与风险分数都落在 [0,1]。

CALM-ZS 与 CALM 都严格使用式 (4) 的四维表示：

```
x_{q,i}^t = ( ζ_{q,i}^t , V_i^t , ψ_{q,i}^t , 1 − R_{q,i}^t )  (17)
```

各组成因子在任一策略生效**之前**就已聚合为 ψ_{q,i} 与 R_{q,i}，并不使用单独的七项准入分数。

**免训练 CALM-ZS 策略。** CALM-ZS 通过取四个共享特征的均匀平均来实现式 (5) 的免训练分支：

```
F_zs(x_{q,i}^t) = (1/4)( ζ_{q,i}^t + V_i^t + ψ_{q,i}^t
                         + (1 − R_{q,i}^t) )                  (18)

g_{q,i}^{zs,t} = h_{q,i}^t · I( F_zs(x_{q,i}^t) ≥ θ_zs )      (19)
```

对应实现中 θ_zs = 0.50。权重与阈值都是固定的，CALM-ZS 不训练任何门控参数。被准入的记忆按 F_zs 排序，上游相关性只用于打破并列。

**可学习 CALM 门控。** 使用一个轻量 MLP 对完全相同的四维表示打分：

```
F_learn(x_{q,i}^t) = σ( f_φ(x_{q,i}^t) )                      (20)

g_{q,i}^{learn,t} = h_{q,i}^t · I( F_learn(x_{q,i}^t) ≥ 0.50 ) (21)
```

因此，学习式与免训练策略只在资格分数上不同，检索候选、硬过滤器、输入特征与上下文装填规则完全一致。学习式资格阈值固定为 0.50。

**资格监督。** 一条被检索的记忆只有在同时满足「为回答查询提供了必需证据」「满足查询条件」「不引入误导性信息」时，才获得正的资格标签：

```
y_{n,i} = I( Support(q_n, m_{n,i}) = 1 )
          × I( Compatible(q_n, m_{n,i}) = 1 )
          × I( Mislead(q_n, m_{n,i}) = 0 )                    (22)
```

这些谓词基于基准标注、查询信息与记忆出处，用确定性规则构造，独立于门控预测和回答模型计算，并在门控优化之前就已固定。具体来说：Support(q, m) 只利用可得的开发集答案监督与证据出处，识别回答 q 所需的直接证据或必要的中间证据；Compatible(q, m) 评估时间、实体、范围与意图的兼容性；Mislead(q, m) 识别被驳斥、已过时、时间不对、范围不相容或依赖失效的证据。

因此，正例既是支撑答案的、又是安全的；负例既包括无关记忆，也包括语义相关但不安全的记忆。后一类作为**困难负例**进入附录 B.5 描述的加权二元交叉熵门控训练目标。

门控训练样本只由经过同一套检索与记忆流水线处理的开发实例构成。评测问题、参考答案及其关联记忆图一律排除在训练之外。生命周期信号可以作为输入特征，但不直接用作监督标签。训练集与评测集按用户和问题互不重叠；与每道题相关的所有记忆和图边都留在对应划分内。

### A.5 在线更新与上下文构建（Online Updating and Context Construction）

在每个交互步，CALM 适配新暴露的后端记录、合并完全重复项、更新局部冲突与依赖链接、重算有效性与生命周期状态，并把活跃与不活跃的记忆连同其证据和有效性区间一起持久化。

在查询时，后端返回 R_q。CALM 计算式 (17) 的四个特征，施加公共硬过滤器，随后按分支使用式 (19) 或式 (21)。存在强冲突的幸存记忆在序列化之前先做消解。被准入的记忆按贪心方式装填，直到再放下一条就会超出记忆 token 预算为止；被拒绝的以及因预算丢弃的记忆都留在持久存储中。

关系更新只在有界的候选邻居集合内进行。因此，查询时门控只需要 O(|R_q|) 次特征计算与门控评估，与存储记忆的总数无关。

**基线。** 我们把 CALM 与四个代表性的长期记忆系统对比，它们覆盖了不同的记忆构建、组织与检索范式。

- **Mem0**（Chhikara et al., 2025）是一个可扩展、面向生产的记忆框架，从进行中的对话里动态抽取、整合、更新与检索显著信息。它主要把记忆表示为紧凑的文本记录，另有一个基于图的变体用于建模实体与记忆条目之间的关系。
- **MemOS**（Li et al., 2025）把记忆当作一种可管理的系统资源，提供统一框架来表示、调度、检索与演化不同形态的记忆，包括纯文本记忆、基于激活的记忆与参数级记忆。
- **EverMemOS**（Hu et al., 2026）提出一个受生物印迹启发的自组织记忆操作系统。其记忆生命周期包含情景痕迹形成、语义巩固与重构式回想，使信息能在长交互历史中被逐步组织与召回。
- **LightMem**（Fang et al., 2025）是一个轻量的记忆增强生成框架，把信息组织为感觉、短期与长期三个记忆阶段，在降低存储与推理开销的同时强调高效的记忆整合与检索。

对每个外部基线，我们都使用其官方实现，并保留原生的记忆构建、存储、整合与检索流水线。我们**不**用 CALM 的检索器替换基线检索器，因为检索与记忆组织本身就是被评测端到端系统的组成部分。改造仅限于数据集转换、回答模型接口与输出格式；在相应实现允许的前提下，回答模型、生成提示词、解码配置与评审器在各方法之间保持一致。

### B.2 记忆后端与检索配置

**记忆后端。** 在 CALM 实验中，上游后端暴露由基准导出的记录，并完成初始索引与候选检索。阶段 I 把返回的记录转换为生命周期治理所使用的规范化记忆单元表示。CALM 不修改上游检索过程。

**候选检索。** 检索分数 ζ_{q,i} 是 CALM 全部实验中所用的固定混合检索模块产生的归一化相关性分数。

```
R_q = TopK_{m_i ∈ M_t} ζ_{q,i} ,      k = 48            (23)
```

在这一步之后 CALM 不再引入第二个检索器。候选检索每道题只执行一次，所得候选与分数全部缓存。CALM-ZS、CALM 与所有 CALM 消融变体复用同一批缓存结果，因此它们之间的差异只来自生命周期治理与查询条件化准入。

**排序与上下文装填。** Relevance-Only 仅按 ζ_{q,i} 对共享候选集排序。CALM-ZS 与 CALM 则使用式 (4) 的公共表示、式 (5) 的分数与式 (6) 的准入规则。被准入的记忆按其策略分数排序，以 ζ_{q,i} 打破并列，再在记忆 token 预算下贪心装填。除非另有说明，全上下文预算为 B = Full token，且只作用于序列化的记忆块。

**错误记忆注入。** 注入在检索之后、门控之前进行。在注入比例 r 下，用 round(rk) 条主题相关但已过时、被驳斥或被取代的记忆替换等量的原始候选，同时保持

```
|R_q^r| = |R_q| = 48                                       (24)
```

注入集合只生成一次，由 CALM、Relevance-Only 以及去掉阶段 III 的变体共同使用。

### B.3 回答模型

我们用三个回答模型评测 CALM：

- Qwen3-30B-A3B-Instruct-2507
- GPT-4.1-mini
- GPT-4o-mini

Qwen3-30B-A3B-Instruct-2507 作为消融与诊断实验的主骨干，GPT 骨干则用于评估跨模型泛化。Qwen3 生成的输出用 qwen-turbo 评审，GPT-4.1-mini 与 GPT-4o-mini 生成的输出用各自对应的模型评审。被比较的方法使用相同的答案生成与评测提示词，且评审器不会被告知被评测方法的身份。

### B.4 评测协议

所有对话都按时间顺序处理。交互步 t 之后可得的记忆，只由截至该步可得的观察来构建，防止未来交互泄漏进记忆构建或查询回答。除非另有说明，在比较 CALM-ZS、CALM 及其消融变体时，使用同一批检索候选集、记忆 token 预算、回答模型、解码配置与评审器。候选采样、错误记忆注入与门控训练统一使用固定随机种子 42。

**回答准确率。** 记 Q 为评测问题集合，I_q 表示问题 q 的生成答案是否被判为正确，则总体回答准确率为

```
ACC = (100 / |Q|) · Σ_{q∈Q} I_q                            (25)
```

对 LongMemEval-S，我们分别报告六个类别的准确率：

- 单会话用户信息（SS-User）
- 单会话偏好（SS-Pref.）
- 单会话助手信息（SS-Asst.）
- 知识更新（K-Upd.）
- 多会话推理（Multi）
- 时间推理（Temp.）

对 LoCoMo，则报告单跳（S-Hop）、多跳（M-Hop）、开放域（Open）与时间（Temp.）四类问题的结果。

**记忆选择指标。** 对每个查询 q，记 R_q 为检索候选集，A_q ⊆ R_q 为门控在基于预算的上下文装填之前准入的记忆。记 E_q 为在该查询下错误或不合格的检索记忆（包括过时、被驳斥、被取代或其他误导性记录），U_q 为为参考答案提供有效证据的检索记忆，F_q ⊆ E_q 为与查询兼容证据直接冲突的检索记忆。

我们报告语料级、按微平均计算的记忆选择指标：先把所有评测问题上的记忆计数聚合，再除以相应的聚合分母。

**错误记忆阻断**衡量被门控拒绝的错误检索记忆占比：

```
EMB = 100 · Σ_{q∈Q} |E_q \ A_q| / Σ_{q∈Q} |E_q|            (26)
```

**有用记忆保留**衡量挺过门控的、有效支撑答案的检索记忆占比：

```
UMR = 100 · Σ_{q∈Q} |U_q ∩ A_q| / Σ_{q∈Q} |U_q|            (27)
```

**冲突泄漏**衡量门控之后仍然留下的、直接冲突的检索记忆占比：

```
CL = 100 · Σ_{q∈Q} |F_q ∩ A_q| / Σ_{q∈Q} |F_q|             (28)
```

EMB 与 UMR 越高越好，CL 越低说明对冲突证据的抑制越强。如果某道查询的分母集合中没有记忆，它对分子与分母的贡献都为零。只有当某个指标在整个评测集上的聚合分母为零时，才省略该指标。

**证据覆盖诊断。** 仅凭回答准确率，无法区分「检索失败」与「正确证据已进入上下文后的推理失败」。因此我们在三个阶段测量「答案会话覆盖率」：初始检索、门控后准入、最终上下文装填。记 G_q 为包含回答查询 q 所需证据的金标准会话集合，S_q^z 为阶段 z ∈ {ret, gate, pack} 下被选中记忆所覆盖的会话。与上面语料级微平均的记忆选择指标不同，下列覆盖指标在评测问题上做**宏平均**：

```
Hit_z       = (100/|Q|) · Σ_{q∈Q} I[ G_q ∩ S_q^z ≠ ∅ ]     (29)

FullHit_z   = (100/|Q|) · Σ_{q∈Q} I[ G_q ⊆ S_q^z ]         (30)

AvgRecall_z = (100/|Q|) · Σ_{q∈Q} |G_q ∩ S_q^z| / |G_q|    (31)
```

我们还报告 **packed-hit accuracy（装填命中准确率）**，衡量「装填后的上下文中至少包含一个金标准证据会话」的那些问题上的回答准确率：

```
PHA = 100 · Σ_{q∈Q} I_q · I[ G_q ∩ S_q^pack ≠ ∅ ]
        / Σ_{q∈Q} I[ G_q ∩ S_q^pack ≠ ∅ ]                   (32)
```

**表11：检索、门控与上下文装填各阶段的证据覆盖诊断。所有数值均以百分比给出。**

| 阶段 | Hit ↑ | FullHit ↑ | AvgRecall ↑ |
|---|---|---|---|
| Initial Retrieval（初始检索） | 100.00 | 94.80 | 97.99 |
| Post-Gating（门控后准入） | 100.00 | 94.60 | 97.84 |
| Final Packing（最终装填） | 100.00 | 93.00 | 97.18 |

| 附加指标 | 数值 |
|---|---|
| Packed-Hit Accuracy | 79.6 |

PHA 只在其聚合分母非零时报告。这些诊断能定位错误究竟来自：证据缺失、门控导致的证据丢失、基于预算的截断，还是「证据已成功覆盖但推理不正确」。

### B.5 实现与训练细节

**记忆处理流水线。** 每段对话都要经过记忆适配、生命周期治理、检索、查询条件化门控、上下文装填、答案生成与自动评测。CALM-ZS 与 CALM 接收相同的检索候选和相同的四维输入 [ζ_{q,i}^t, V_i^t, ψ_{q,i}^t, 1 − R_{q,i}^t]。CALM-ZS 使用式 (18) 与 (19) 的固定分数与准入规则，CALM 使用式 (20) 与 (21) 的学习分数与准入规则；两种策略使用同一个硬性资格过滤器和同一套查询—记忆特征。

**可学习门控。** 门控是一个单隐层 MLP，隐层激活为 GELU、输出为 sigmoid，在「资格监督」一节定义的查询—记忆样本对上以加权二元交叉熵训练。学习式门控阈值固定为 0.50，免训练阈值见附录 A.4。门控与回答模型分开训练，回答模型、检索器与记忆后端的参数都不更新。

门控训练样本对来自一个独立的开发集，与所报告的评测实例互不重叠；LongMemEval-S 与 LoCoMo 的任何评测问题、参考答案或关联记忆图都不参与门控优化。困难负例包括语义相关但已过时、相互冲突、时间不对、范围不相容以及依赖失效的记忆。CALM-ZS 不需要训练。

### B.6 详细消融协议

所有消融都在 LongMemEval-S、骨干为 Qwen3-30B-A3B-Instruct-2507 上评测。检索候选集、相关性分数、答案生成提示词、解码设置、评审器与记忆 token 预算在各变体之间固定。分阶段与组件级结果见正文表4和表5。

**分阶段消融。** 每个变体去掉一个阶段，并用同一批缓存候选与同一套答案生成协议重算下游量。

- **w/o Stage I**：直接使用后端的原始记录，不做规范化适配，也不做证据对齐。
- **w/o Stage II**：跳过生命周期图构建、存储有效性更新与生命周期状态治理；显式时间元数据仍可用于查询时匹配。
- **w/o Stage III**：保留前两个阶段，但禁用硬性资格过滤与阈值化准入，改由上游相关性排序后再进入共享的上下文装填步骤。
- **CALM-ZS**：用附录 A.4 描述的固定四特征策略与 0.50 准入阈值替代学习式打分。

**生命周期与门控消融。** 这些变体去掉单个组件，并重算受影响的生命周期或准入决策。

- **w/o Conflict**：去掉冲突链接与冲突风险信号。
- **w/o Temporal**：去掉时间匹配、错配风险，以及冲突消解和生命周期治理中的时间线索；完整方法本身没有「仅凭时间」的自动老化转移。
- **w/o Validity**：从查询时选择中去掉存储有效性特征 V_i^t。
- **w/o Compatibility**：去掉 ψ_{q,i}^t；**w/o Risk** 去掉 1 − R_{q,i}^t。所有受影响的分数与决策都在相应消融设置下重新计算。

**简单过滤与重排序基线。** 所有策略使用完全一致的阶段 I 单元、缓存的 top-48 候选 R_q、相关性分数 ζ_{q,i}、回答模型、解码设置、上下文序列化、评审器与名义记忆 token 预算。任何方法在推理时都不访问评测答案或标签。

- **Temporal-Filter** 只在其显式声明的适用区间与查询目标时间不相容时才拒绝一条记忆。记 T_q 与 T_i^src 为这两个区间：

```
R_q^TF = { m_i ∈ R_q : χ_{q,i}^time = 1 }                  (33)
```

  其中 χ_{q,i}^time 仅在两个区间都已知且互不相交时取 0，否则取 1。存活的记忆保持相关性顺序。该基线不推断取代关系，也不使用生命周期状态。

- **Recency-Rerank** 保留全部候选，把相关性与观察时间的名次结合：

```
h_i = 1 − (r_i − 1) / max(1, |R_q| − 1)
s^RR_{q,i} = (1/2)( ζ_{q,i} + h_i )                        (34)
```

  其中 r_i = 1 表示最新的记忆；缺失时间戳取得最低名次；当 |R_q| = 1 时 h_i = 1。

- **Validity-Rerank** 保留全部候选，把相关性与阶段 II 的存储有效性结合：

```
s^VR_{q,i} = (1/2)( ζ_{q,i} + V_i )                        (35)
```

  它不使用 ψ_{q,i}、R_{q,i}，也不使用 CALM 的准入决策。两个重排序器都采用固定等权、不在测试集上调参；并列时以上游相关性打破。

**严格匹配的准入对照。** 为了拆开「硬过滤」「排序」「阈值化准入」三者的作用，我们在同一批阶段 I 单元与缓存候选上追加三个对照。记

```
H_q = { m_i ∈ R_q : h_{q,i} = 1 }                          (36)
```

  为通过 CALM-ZS 与 CALM 同一个硬性资格过滤器的幸存集合。所有对照都对 H_q 排序，并使用完全相同的贪心上下文装填规则，不再施加任何准入阈值。

- **Hard Filter + Relevance**：按 ζ_{q,i} 排序 H_q。
- **Hard Filter + Validity-Rerank**：按式 (35) 的 s^VR_{q,i} 排序。
- **Hard Filter + Learned Rerank**：用 CALM 同一个已训练 MLP 与同一套特征按 F_learn(x_{q,i}) 排序，但把所有硬性合格候选都放进排序池，不施加 0.50 的学习式门控阈值。因此它与 CALM 的对比，孤立出「学习式排序之外、阈值化二元准入」的增量作用。该对照不重新训练 MLP。

**匹配准入对照的分析。** 如表12所示，硬过滤能改善基于有效性的重排序，而引入存储有效性优于仅用相关性选择；学习式重排序再进一步提升，但仍然低于 CALM，说明阈值化准入相对单纯排序是有价值的。在过滤与装填规则完全相同的前提下，CALM 也优于 CALM-ZS，支持学习式资格打分的收益。综合来看，这些结果说明**生命周期感知过滤、基于有效性的排序与查询条件化的准入各有贡献**，而不是依赖某一个启发式。

**表12：LongMemEval-S 上匹配的检索后准入控制的示意性对比。所有方法共享检索候选、回答模型与记忆 token 预算。**

| 检索后策略 | Acc. (%) |
|---|---|
| Validity-Rerank | 77.20 |
| CALM-ZS | 76.60 |
| CALM | **79.60** |
| Hard Filter + Relevance | 76.00 |
| Hard Filter + Validity-Rerank | 78.00 |

**选择动作与对比范围。** 原始的简单基线检验的是显式时间拒绝或重排序，不含 CALM 的硬过滤器；匹配对照则进一步分离出硬过滤器（Validity-Rerank 对 Hard Filter + Validity-Rerank）与准入阈值（Hard Filter + Learned Rerank 对 CALM）的作用。CALM-ZS 与 CALM 本来就共享同一硬过滤器、同一特征与同一装填规则，因此可以孤立出「固定 vs. 可学习」资格打分的差别。与 Hard Filter + Relevance 不同，w/o Stage III 变体是彻底移除硬过滤。这些对比固定了检索与名义上下文预算，但不固定装填记忆的数量或呈现顺序，因此它们评估的是选择机制本身，并不假设各方法的实际上下文长度相同。

### B.7 记忆保留与冲突鲁棒性

为评估对冲突证据的鲁棒性，我们把主题相关但已过时、被驳斥或被取代的记忆注入检索候选集，注入比例从 0% 到 50% 不等。注入在检索之后、记忆选择或门控之前进行，候选集规模与最终记忆 token 预算在各方法之间保持恒定。我们把 CALM 与两个基于相关性的对照比较：Relevance-Only 代表既无生命周期也无兼容性控制的「纯检索」策略；w/o Stage III 则在保留生命周期管理的记忆表示的同时，移除 CALM 的查询条件化准入模块。这两个对照合起来，可以把「检索排序的效应」与「生命周期感知的准入」区分开。

如表13所示，随着错误记忆污染加重，所有方法的准确率都会下降；但 CALM 始终取得最高准确率，且性能下降幅度明显更小。从 0% 到 50% 注入，CALM 只损失 7.0 个百分点，而 Relevance-Only 与 w/o Stage III 分别损失 11.6 和 16.8 个百分点。相应地，CALM 相对这两个变体的准确率优势从 4.4 和 5.8 个百分点扩大到 9.0 和 15.6 个百分点。随着被检索证据越来越不可靠，这一不断拉大的差距凸显了**生命周期感知记忆准入**的重要性。

互补的阻断与保留测量进一步表明：CALM 在抑制误导性记忆的同时保住了有用证据。在六个注入水平中的五个上，CALM 都阻断了超过 70% 的错误记忆（20% 注入处有短暂回落）；与此同时，有用记忆的保留率在整个注入扫描中保持稳定，说明更严格地拒绝错误记忆并不必然按比例移除支撑答案的证据。这一鲁棒性分析聚焦受控记忆污染下的回答准确率，是对表3中语料级 UMR 的补充。综合来看，CALM 在「冲突鲁棒性」与「有用记忆保留」之间取得了良好平衡。在 0% 注入时，EMB 是在原始检索候选集中自然存在的错误记忆上计算的。

| 变体 | 0% | 10% | 20% | 30% | 40% | 50% |

### B.8 历史重建

历史重建实验要评估的是：一个记忆系统能否在不让更早状态干扰当前状态推理的前提下保留它们。我们评测所有被识别出的「更新链」——即至少包含一个早期状态和一个后期替换的链条，涵盖住址、偏好、资料属性、约定与事实状态的变化。

每条保留下来的更新链对应两类配对查询。**当前状态查询**询问最近一次更新之后生效的状态；**历史状态查询**询问某次指定更新之前、或某个更早区间内生效的状态。成对的查询使用同一套底层存储库与检索流程，因此要答对，就必须依赖**查询条件化的记忆使用**，而不能靠存了不同的内容。

我们比较四种记忆管理策略：**Keep-All** 保留并准入所有记录；**Latest-Only** 只保留更新链中最近的一条记录；**Relevance-Only** 保留所有记录但仅按语义相关性选择，不做生命周期或兼容性控制；**CALM** 同时保留较早与较晚的记录，并用查询条件化门控决定哪个状态进入工作上下文。

准确率对当前状态问题与历史状态问题分别计算。CALM 在当前状态问题上比最强替代方案高 3.71 个百分点，在历史状态问题上高 9.26 个百分点。历史查询上更大的提升说明：**在当前状态推理中压制一条被取代的记忆，并不需要把它从持久存储里删掉。**

### B.9 效率测量

**上下文预算评测。** 我们在 512、1024、2048 与 Full 四档记忆 token 预算下评测准确率，其中 Full 对应主实验的全上下文设置。该预算只作用于序列化的记忆块，不包含系统指令、问题与固定的答案生成模板。

门控在基于预算的装填之前执行。通过门控的记忆按各自策略的资格分数排序，依次加入上下文，直到再加一条就会超出预算为止。这一协议把「门控导致的拒绝」与「预算导致的截断」分开。上下文预算图所依据的精确准确率数值见表14。

**token 核算。** 记忆 token 用量在最终装填的记忆上下文序列化之后测量：

```
MemTok = (1/|Q|) · Σ_{q∈Q} Tok(C_q)                        (37)
```

其中 Tok(C_q) 是被准入并装填的记忆所占的 token 数。该指标不含固定的系统提示词、问题 token 与生成答案的 token。我们还记录被检索、被门控准入、被装填、被门控拒绝，以及因上下文预算而遗漏的记忆条数；这些计数可以区分「由有效性感知选择造成的减少」与「单纯截断造成的减少」。

**延迟核算。** 延迟按查询测量，在完整评测集上取平均。检索延迟覆盖候选检索与检索侧预处理；门控延迟覆盖查询—记忆特征构造以及 CALM-ZS 或学习式门控的施加；答案延迟度量回答模型的调用。总延迟则独立地按端到端墙钟时间测量：

```
T_total = T_retr + T_gate + T_pack + T_ans + T_other        (38)
```

其中 T_other 包含序列化、编排与其他固定的查询处理开销。因此，四舍五入后的检索、门控与答案分量之和不一定恰好等于独立测得的总延迟。

CALM-ZS 与 CALM 在同一执行设置下测量，二者的差值即隔离出额外的学习式门控开销。EverMemOS 使用其原生回想流水线评测，没有单独的 CALM 门控阶段，因此它所报告的「检索/门控」条目只包含该流水线实际执行的操作。离线构建与门控训练的开销不计入查询时延迟；用于门控训练的 NVIDIA A100 80GB GPU 也与在线检索、门控和答案生成分开报告。

**表14：LongMemEval-S 上不同记忆 token 预算下的精确准确率（%）。**

| 方法 | 512 | 1024 | 2048 | Full |
|---|---|---|---|---|
| EverMemOS | 29.60 | 53.80 | 62.40 | 66.40 |
| CALM-ZS | 38.00 | 58.40 | 69.80 | 76.60 |
| **CALM** | **39.20** | **60.20** | **74.60** | **79.60** |

### B.10 提示词（Prompts）

#### B.10.1 LongMemEval 提示词

本节给出 LongMemEval-S 上用于答案生成与自动评测的提示词模板。所有骨干模型与被比较的方法都遵循同一套统一的答案生成协议。花括号内的字段（如 {question}、{context}、{question_date}）对每个评测实例动态实例化，不针对单个实例做任何手工修改。

**答案生成协议。** 对 LongMemEval-S 的所有问题，无论其是否可回答，我们都使用同一个统一的答案生成提示词。提示词的选择不使用问题标识、可回答性标注、参考答案或评测标签；该协议在各方法之间一致。

**统一答案生成提示词（Unified Answer Generation Prompt）**

```
You are a long-term memory assistant. Answer the question using only the supplied memories. Some questions may not be answerable from the available evidence.
Do not guess personal details or infer unsupported facts.
If the memories do not contain sufficient evidence, explicitly state that the information is unavailable.
Otherwise, return a concise answer grounded in the supplied memories.
Resolve knowledge updates and temporal references using the time requested in the question.

TASK CONTEXT
Dataset: LongMemEval
Question type: {question_type}
Question date: {question_date}

QUESTION-SPECIFIC RULES
{type_rules}

MEMORIES
{context}

QUESTION
{question}

Answer:
```

**题型专属指令。** LongMemEval 的不同问题类别需要不同的记忆解读方式与证据聚合方式，因此我们在统一答案生成提示词中按问题类型实例化 {type_rules}；这一选择与可回答性及评测标注无关。各条指令的中文说明与英文原文如下：

- **单会话用户任务（Single-Session User Tasks）**——答案应当来自某个相关会话中的用户消息。
```
The answer should come from a user message in one relevant session.
```
- **单会话助手任务（Single-Session Assistant Tasks）**——答案应当来自助手此前的回复，而不能只来自用户的请求。
```
The answer should come from the assistant's previous response, not from the user's request alone.
```
- **多会话任务（Multi-Session Tasks）**——优先使用 MULTI-SESSION COVERAGE，合并所有相关会话；若问题问的是计数、列表、比较、顺序或多个事实，则在作答前逐条核对每个带日期的用户提及项，只统计互不相同的用户提及项，不要把不同的动作合并成一项。
```
Use MULTI-SESSION COVERAGE first. Combine all relevant sessions. If the question asks for a count, list, comparison, order, or multiple facts, check each dated user-mentioned item separately before answering; count distinct user-mentioned items only and do not merge separate actions into one.
```
- **时间推理任务（Temporal Reasoning Tasks）**——优先使用 TEMPORAL EVIDENCE TABLE；利用给定的相对日期说明归一化相对表述，识别相关带日期事件，再给出最终的日期、顺序、时长或事件名。若问题问的是事件 A 比事件 B 早／晚多久，就计算 A 到 B 的间隔；只有当问题以「今天」或「问题日期」为基准时，才使用与问题日期的距离。
```
Use the TEMPORAL EVIDENCE TABLE first. Normalize relative phrases using any supplied relative-date notes, identify the relevant dated events, then answer with the final date, order, duration, or named event. If the question asks how long event A was before or after event B, compute A-to-B; use distance from the question date only when the question asks relative to today or the question date.
```
- **知识更新任务（Knowledge Update Tasks）**——优先使用 KNOWLEDGE UPDATE TABLE；若新旧记忆冲突，以最新且有支撑的更新作为最终答案。
```
Use KNOWLEDGE UPDATE TABLE first. If older and newer memories conflict, use the newest supported update as the final answer.
```
- **单会话偏好任务（Single-Session Preference Tasks）**——优先使用 USER PREFERENCE CLUES；依据用户稳定或最近的偏好、约束与资料作答，而不是给出泛泛建议；在最终答案中点明具体记住的偏好或情境。
```
Use USER PREFERENCE CLUES first. Answer from the user's stable or most recent preference, constraint, or profile instead of generic advice; mention the specific remembered preference or context in the final answer.
```
- **默认任务（Default Tasks）**——直接依据最相关的、有支撑的记忆作答。
```
Answer directly from the most relevant supported memories.
```

#### B.10.2 LoCoMo 提示词

本节给出标准 LoCoMo 基准上用于答案生成的提示词模板。除非另有说明，所有骨干模型使用同一提示词。花括号内的字段（包括 {question}、{question_type}、{speaker_1_memories}、{speaker_2_memories}）对每个评测实例动态实例化，不做逐实例的手工修改。

LoCoMo 问题分为四类：单跳、多跳、时间与开放域。每个实例都通过 {category_rule} 字段，把对应的类别专属指令插入通用答案生成提示词。

**答案生成提示词说明。** 模型被要求先确定目标说话人，必要时跨记忆表示整合证据，用相关的会话时间戳解决时间表达式，并且只返回一个简短的最终答案。

**题型专属指令。** LoCoMo 的不同问题类别需要不同的证据选择、跨会话聚合、时间归一化与常识推理方式，因此我们向通用答案生成提示词中插入一条类别专属指令：

- **单跳问题（Single-Hop Questions）**——找到直接陈述所求事实的那一条记忆，保留准确的名称、地点、对象、数量与日期。
```
Find the one memory that directly states the requested fact. Preserve exact names, places, objects, quantities, and dates.
```
- **多跳问题（Multi-Hop Questions）**——合并所有相关记忆（可能来自不同会话或不同说话人）；答案必须覆盖问题的每一个部分，而不是照抄某一条支撑事实。
