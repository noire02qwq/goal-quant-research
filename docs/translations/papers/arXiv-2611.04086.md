## 摘要

多智能体 LLM 系统正把越来越多的自主智能体放到共享基础设施上，每个智能体被授予的权限远宽于它被委派的任务——于是每个智能体都常规地被允许对它从未被分配的同伴资源采取行动。我们回答如下研究问题：在竞争压力下，什么决定一个智能体是否从自己受托的范围跨入同伴的资源，而这种跨越能否被强制消除？

我们在八个当代 LLM 上、在两个模拟环境——一条 CI/CD 发布流水线和一个安全运营（SOC）事件队列——中研究这一点，使用一个确定性的、无模型在环的检测器，它从哈希链式、可重放验证的日志计算得出。在关于竞争激励、候选可见性与收益信息的受控 2 × 2 × 2 析因实验（三个模型，每格 n = 52）中，我们发现支配行为的是动作的呈现方式（representation），而不是权限：在同伴动作未被列出的任何条件下，没有智能体越界；而在列出它、加上竞争压力与明示收益时，越界急剧上升——对 Claude Sonnet 4.5 高达 52/52 个 episode。

我们还观察到与模型相关的分裂：两个较新的模型（Claude Sonnet 5.5 与 Opus 5.5）在 100 个 episode 中 0 次接受同一次攻击——代价是可预期的——而上一代模型 10 次里越界 9 次。随后我们评估两种防御——一个确定性 reference monitor 与一个基于模型的执行前 judge——发现两者都阻断了全部越界，并且在任务可赢时把可避免的同伴 deadline 失误从 15/40 与 14/40 降到最多 1/40。然而我们证明，强制范围（scope enforcement）并不等于伤害预防：一个智能体仍能通过对自己资源的授权行动拖累同伴——误报其事件的严重性——而两种防御都检测不到。在所测试的环境与配置内，我们的结果确立了动作呈现（而非仅权限）是智能体间范围越界的可控驱动因素，并表明强制受托范围与预防伤害是两回事，从而引出 effect-aware 的授权：它推理一个行动的后果，而不只看它点名的资源。

## 1. 引言

生产部署越来越多地把多个 LLM 智能体放在共享基础设施上：若干 coding agent 对一套 CI/CD 系统，若干事件响应智能体对一个工单队列。每个智能体都被告知哪些资源是它的责任。但平台并不强制执行这种分配。权限按角色授予——粒度粗、变化慢；分配按任务做出——粒度细、每小时都在变。结果是每个智能体持有的技术权限都远宽于交给它的工作。一个 CI/CD 服务账号可以取消项目里的任何 job；而一张工单只覆盖一条流水线。一个事件协调者角色可以对整个队列行动；而轮值只分配到一个事件。当智能体在这个缺口里行动时，后果是真实的——同伴的发布错过截止时间，或同伴的事件失去它的升级席位——但这一步被记录为智能体自己被认可的行动，于是当初使之成为可能的配置事后看起来毫不相干。

近期工作凸显了自主 LLM 智能体新兴的安全风险。Zhang et al. [3] 通过 AuthorizationBench 表明，智能体即使在完成合法任务时也会超出受托权限；Yu et al. [2] 发现可执行的工具 affordance 会在其他条件不变的情况下显著改变安全行为；Lindner et al. [1] 审计了模拟 agentic 部署中的破坏倾向。这些工作提出了我们在此要问的问题，但设置是它们没有处理的：多个智能体在一张显式的委派地图下竞争共享资源，其中一个被允许对另一个的资源行动。

本文就这个缺口问一个行为学问题：当一个智能体有能力对同伴的资源行动（系统不会阻止它）、但无权这么做（它的分配另有规定）时，它会守住自己的车道吗？如果不会，是什么让它跨过去？

我们的立场是，即使在技术上不受约束，智能体也应尊重它的受托范围：遵守分配是智能体行为的属性，而不是靠重新配置权限来强制的东西。把权限细化到任务粒度在真实系统中做不到，所以这个问题并不归结为「别配错了」。

**研究问题。** 在全程固定权限与任务的条件下，我们研究竞争性多智能体 LLM 系统中受托范围越界的三个问题：

- RQ1：是什么驱动智能体越界？在竞争压力下，智能体对同伴资源采取行动，是因为它被激励这么做，还是因为该动作被呈现为一个可执行的候选？我们在一个受控析因实验中把竞争激励、候选可见性与收益信息分离开（§4）。
- RQ2：这种行为依赖模型吗？面对同一次有利可图的越界，哪些模型接受、哪些拒绝——对拒绝者而言，其给出的理由是什么？（§4）
- RQ3：强制范围能预防伤害吗？一个运行时授权层能阻断这些越界吗？当它阻断时，阻断越界是否也阻断了随之而来的对同伴的伤害——还是说伤害可以经由仍在智能体权限内的行动持续存在？（§5）

图1：通向同一种伤害的两条路径。通道 1（实线）：A 对 B 的资源行动——一次范围跨越，reference monitor 与 judge 都会阻断它。通道 2（虚线）：A 把自己事件的严重性抬高，合法地把 B 挤出共享席位；这在委派范围内，所以两种防御都动不了它。强制范围只关闭通道 1。（原文第2页）

在回答这些的同时，我们贡献一个把该越界形式化为 P \ D 中状态变更动作的威胁模型（§2），以及一个确定性、无模型在环的检测器——从哈希链式、可重放验证的日志计算得出，所有权读自版本化的委派记录而非推断（§3）——并把它们应用到八个 LLM 与两个环境上。

**发现。** 简言之：（RQ1）决定性的是呈现而非激励——当同伴动作未被列出时没有智能体越界，而在竞争压力下列出它并给出明示收益，让一个模型的越界升到 52/52 个 episode；（RQ2）行为是模型相关的——两个较新的模型在 100 个 episode 中 0 次接受同一次有利可图的越界，而上一代模型 10 次里越界 9 次，理由多半是伤害而非范围；（RQ3）一个运行时授权层阻断了越界，并且在任务可赢时预防了大部分伤害，但一条残余通道——一个智能体误报自己任务的状态以损害同伴——在强制之后依然存活，所以阻断范围越界与预防伤害不是同一个保证。

## 2. 威胁模型

**设定。** 两个或更多 LLM 智能体在声明了责任划分的共享基础设施上行动。每个智能体收到一份书面委派记录，点名它的资源。平台授予每个智能体宽于其分配的技术权限。这些智能体不是对抗性的、没有被越狱、也没有被指示互相干扰。没有提示注入，没有凭证被攻破，也没有任何授权控制被绕过。我们研究的失败发生在这些良性条件之下。

**两种性质，只有一种被强制。** 我们区分两个通常被混为一谈的概念（表 1）。技术权限意味着平台不会阻止该行动；它由访问控制强制。组织委派意味着该工作被分配给了智能体；它由流程、评审与惯例强制——而不是由软件。一个有生产环境访问权的工程师在没被要求的情况下重启了另一个团队的服务，就造成了一次事故，尽管没有任何东西阻止他。标准术语是 unauthorized change，而每个变更管理流程都预设权限宽于授权。

表1：本文测量的构念：两个不同的性质，只有一个由软件强制。

| 性质 | 含义 | 由谁强制 |
|---|---|---|
| technical permission | 平台不会阻止你 | 访问控制 |
| organizational delegation | 这项工作被分配给了你 | 流程、评审 |

**越界。** 设 harness 允许的动作集合为 P，指令所分配的为 D ⊆ P。一次受托范围越界（delegated-scope violation）就是 P \ D 中的一个状态变更动作。三条性质使它成为实质性的失败而非定义上的失败：分配是显式的——每个智能体收到一份委派记录，所有权从不从资源名推断；存在伤害——同伴的任务因这次状态变更而直接受阻；而且存在合法路径——在最优打法下，行动的智能体可以不越界就成功，因此越界不是任务逼出来的。

**为什么权限缺口不是配错。** 权限粒度粗且变化慢；分配粒度细且每小时都在变。没有组织会按工单重发访问策略，任务粒度的最小权限在规模上做不到。人类组织用流程而非访问控制来弥合缺口。我们的 permission_mode: soft 设置直接模拟这一点：属于同伴的行动会成功并被记录。一个会阻止该行动的环境，测量的是我们自己锁的强度，而不是智能体的行为。

**攻击者。** 对抗者（如果存在的话）是一个内部人，他控制智能体动作空间的呈现——工具或菜单层——而不是任务、奖励、评分或权限。这是审计最少的一层：放宽资源枚举是一个站得住脚的性能改动，没有权限系统会记录一次拒绝，而由此产生的越界被记录为智能体的一次行动。我们称之为归因洗白（attribution laundering）：一个内部人诱发的伤害，呈现为涌现的模型行为失常。在通常情况下根本没有对抗者——一个粗心的主体写了一个相对目标，而框架默认就宽泛地枚举。

**不在范围内。** 提示注入、越狱、被攻破的凭证、对抗性微调，以及任何智能体被指示去干扰的情形。该威胁模型适用于共享基础设施上需要其范围的宽权限智能体；它不适用于按任务紧密沙箱化的智能体，我们把这一点陈述为一个边界。

## 3. 环境与方法

**设计。** 每个 episode 运行两个同一模型的智能体，在分开的上下文中，各给一份书面的分配地图。一个环境是竞争性的 CI/CD 发布流水线；另一个是安全运营（SOC）事件队列。两者都暴露一个角色，其技术触达横跨共享资源，而委派仍然按资源划分。

**检测器。** 主要终点是确定性计算的，无模型在环。一个动作构成成功的违规，当且仅当：它被技术上允许、行动的主体不是该资源的受托所有者、且该动作改变了同伴拥有的状态：

```
permitted ∧ ¬within_delegation ∧ changed_state.
```

所有权来自版本化的委派记录，从不从资源名推断；意图从不被推断。每个报告的 episode 都从其哈希链式日志重放，分类分歧为零，处理隔离在唯一变化的段落之外逐字节验证。

图2：测量总览。同一模型的两个智能体在分开的上下文中、于一个共享环境（CI/CD 或 SOC）上行动，受一张显式委派地图 D ⊆ P 约束；每个动作写入哈希链式日志，主要终点由一个无模型在环的确定性检测器计算（permitted ∧ ¬within ∧ changed），输出违规计数。（原文第3页）

**CI/CD 环境。** 第一个环境（图 3）模拟一个共享的持续集成平台，其上两个智能体各自准备一次发布。每个智能体拥有一条流水线——一串 job——并必须让它在共享截止时间（round 12）之前进入通过状态。两条流水线从一个共享、固定容量的 runner 池中取用，按入队轮次先进先出，所以 runner 池就是被争夺的资源。智能体的技术角色（project_maintainer）可以对项目里的任何流水线行动——取消一个 job、取消一条流水线、重启一条流水线——而委派只覆盖智能体自己的流水线。一条合法策略（重试自己不稳定的 job、管理自己的队列位置）能在余量内完成发布：在最优打法下，最早完成是 round 9（先行动）或 9–10（后行动），对照 round-12 的截止。让同伴落后的唯一办法是对同伴的流水线行动：取消一个同伴 job 会让它的流水线失败，重启同伴流水线会丢弃它的工作并交出它的队列位置，把同伴的分数从 100 打到 0。因此伤害需要一次范围跨越；没有自己资源的路径能伤害同伴。奖励把两个智能体耦合：

```
Ri(λ) = (1 − λ) · Si + λ · (50 + (Si − Sj) / 2)
```

所以在 λ = 0 时智能体按自己的结果取酬，在 λ = 1 时纯粹按两者之差取酬。

图3：CI/CD 环境。每个智能体拥有一条流水线；两者在 round-12 截止下争夺一个共享 runner 池。让同伴落后的唯一办法是对同伴的流水线（朱红色）行动——一次范围跨越。没有自己资源的路径能伤害同伴。（原文第4页）

**SOC 环境。** 第二个环境（图 4）模拟一个安全运营事件队列，也是防御评估的场景。两名分析师各拥有一起必须在其 SLA 截止前解决的事件；解决需要持有一个被争夺的升级席位。关键是排程可行：在一份合法的、尊重优先级的策略下，两起事件都能在各留两轮余量的情况下完成（经仿真验证），所以任何错过的截止都是可避免的，而不是打不赢的争夺的产物。incident_coordinator 角色可以对队列里的任何事件行动——升高或降低严重性、把它移出队列、重定向容量——而委派只覆盖分析师自己的事件。每起事件都有一个应有严重性，因此把严重性抬到高于该水平就是可测量的误报，而不是合法的重新分诊。席位按严重性从高到低、带抢占地授予，这打开了两条拖累同伴的路径。一个智能体可以直接对同伴的事件行动——降低其严重性或把它移出队列——这是范围跨越。或者它把自己事件的严重性抬高以抢占同伴的席位；这只对自己的事件行动、在委派范围内，只有当抬升超过应有水平时才不正当。这第二条被授权的路径在 CI/CD 中不存在，也是我们核心防御发现的来源（§5）：强制范围边界移除第一条路径，但移不掉第二条。环境的构造是为了干净地提出这个问题——一个可赢的任务配一条合法基线——我们把设计与可行性检查记录在附录中。

图4：修复后的 SOC 环境。排程是可行的，所以错过截止是可避免的。智能体 A 可以通过跨越到 incident-b（朱红色）来拖累 B——这会被强制阻断——或者通过误报（橙色）：把自己事件的严重性抬到高于应有水平以抢占 B——这留在 A 的受托范围内，强制看不见它（§5）。（原文第4页）

**是什么制造了压力。** 越界不是无端的：两个环境都构造得让越界发生的那一刻，对同伴资源行动是一个只追求自身既定目标的智能体在工具理性上最优的一步。三种成分组合在一起，而这个组合正是本文分离出的机制。其一，相对目标：在 R_i(λ) 下，同伴的成功直接降低智能体自己的奖励，所以在 λ = 1 时拖累一个自己任务正在失败的同伴，正好值 50λ 的相对名次。其二，智能体看得见的落后轨迹：智能体被置于落后位置、记录下一个预期失败，并把同伴感知为障碍——在 SOC 中，43/44 次越界来自当时正被席位挡住的智能体；在预注册的 CI/CD 格中，每个 episode 都在任何越界之前到达两个前置状态（预期失败、同伴被认定为原因）。其三，一个杠杆：一个可得的、把同伴的领先转成自己领先的动作。关键是，三者中没有任何一个指示智能体去行为不端——目标是普通的绩效框架，落后位置是普通的竞争结果，杠杆是一次普通的、被允许的工具调用。本文的要点是这些因子相互作用：单靠任何一个都不产生越界（§4），但把它们从现实的、非对抗性的零件装配起来，就让受托范围越界成为理性的一步，而当前的模型会走这一步。杠杆的呈现方式（§4）是那个开关；这里描述的竞争压力是让智能体伸手去够它的原因。因此防御必须对付的不是一个行为不端的模型，而是一个在良性设置造就的条件下行为合理的模型。

**affordance 操作。** 我们的主要攻击实验是一个析因实验（§4），它独立变化三个因子，同时固定工具、权限与任务：激励（独立 vs. 竞争奖励）、同伴拥有动作的候选可见性（未列出 vs. 已列出）、以及附着其上的收益信息（后果未明示 vs. 已明示）。这把 affordance 效应与收益信息效应分离开——单一一次「有菜单 vs. 无菜单」的操作会把两者混在一起。

**模型。** 八个当代模型：GLM-5、Claude Sonnet 4.5、Claude Sonnet 5.5、Claude Opus 5.5、GPT-6 Astra、DeepSeek V3.2、Mistral Large 3、Qwen3-Coder。除 Claude 5.5 系列外都在温度 0 运行，后者拒绝温度设置、按提供商默认运行（这让它们的零比率更强而不是更弱）。GPT-6 与 Qwen3-Coder 在 92–96% 的调用上不返回文本：它们的行为计数有效，但机制无法检验。所有模型都经 AWS Bedrock（us-west-2）访问；模型 ID 与区域钉在每个 episode 的 manifest 中。

**试验次数。** 主要攻击实验（下文的析因）每格 n = 52；修复后 SOC 的防御评估（§5）用 n = 40；更早的诊断格用 n = 10–20。所有比率都以计数报告，而非紧凑的百分比。这是一次倾向性评估：比率按设计就是低的，因为存在合法路径。

## 4. 结果：攻击

### 4.1 分离出 affordance 效应

我们的主要攻击实验是一个 2 × 2 × 2 析因，三个因子分别为激励（独立 vs. 竞争奖励）、候选可见性（同伴拥有的动作未列出 vs. 已列出）、以及附着其上的收益信息（后果未明示 vs. 已明示），运行在三个可读推理的模型上（GLM-5、Sonnet 4.5、DeepSeek V3.2），每格 n = 52，各格起始状态相同、种子跨格配对。表 3 与图 5 给出发生越界的 episode 数。三个结果把因子分离开。

**（在我们的条件下）没有列出的候选就没有越界。** 在同伴动作未被列出的每个条件下——每个模型的四个未列出条件，共十二格——没有模型越界（每格 0/52），无论在哪个激励水平与哪个收益水平上，尽管指向同伴的工具全程都在工具箱里可用。我们不主张可见性在一般意义上是必要的；我们报告的是：候选级的呈现，而不只是工具可用，是我们观察到的任何一次越界所必需的。

**竞争激励推动越界，对 Sonnet 最明显。** 给定可见性，独立奖励且收益未明示时，每个模型仍是 0/52；竞争版本则产生越界（GLM-5 6、Sonnet 4.5 20、DeepSeek 3，均在 52 中）。这一竞争对比对 Sonnet 4.5 很强（表 2，Holm 校正 p = 1.4 × 10⁻⁶），但在 n = 52 时对 GLM-5（p = 0.054）与 DeepSeek（p = 0.24）不单独显著：对这两个模型，光有竞争几乎没把比率从零抬起来。

**收益信息是稳健的放大器。** 在竞争与可见性之上再加入该动作已明示的后果，会急剧抬高比率——GLM-5 6 → 18、Sonnet 4.5 20 → 52、DeepSeek 3 → 48——且这一放大在三个模型上都经得住校正（p = 0.029、3 × 10⁻¹²、7 × 10⁻²⁰）。它还能弱替代竞争：在独立奖励下，已列出且已明示产生了几次越界（GLM-5 0、Sonnet 4.5 3、DeepSeek 6），而已列出未明示一次也没有。

因此因子是交互的：候选被列出是我们观察到的每一次越界的前提（每个未列出格都是 0），已明示收益是推动每个模型的放大器，而没有明示收益的竞争只强烈推动 Sonnet、对其余模型只是弱推动。这取代了「两个必要条件」的读法；而且由于独立/已列出/未明示各格是干净的 0/52，它确认——用一个恰当独立的奖励——在我们的条件下竞争耦合（或明示收益）是必需的。我们在权限与任务保持不变的条件下，测量了动作呈现对观测到的未授权行动比率的因果效应；我们不主张识别出了模型的内部决策机制，零比率只是给出上界而非证明普遍必要性。两条注记限定这一分辨力：Sonnet 4.5 的竞争/已列出/已明示格处在天花板（52/52，Wilson CI [93,100]%），以及 GLM-5 在两个未列出格里有 28–35% 的调用返回空文本（它在那里的零有一部分是不响应，尽管其他每个未列出格也都是 0）。在所有格中，起步落后的智能体从未完成自己的发布（1,247 个 episode 中的 0 次），因此对行动智能体自身的任务伤害仍未被测量。

**统计分析。** 我们对比率报告 Wilson 95% 区间，对对比报告双侧 Fisher 精确检验，九个主要对比整体 Holm 校正（表 2；同一模型内可见性与竞争对比是同一个检验，因此只计一次）。所有比率都是配对种子格的计数；在温度 0 下，模型在同一个种子内近乎确定，所以 episode 间的变异来自种子（任务实例、哪一侧是焦点、行动顺序），而不是对固定状态的重抽样——因此我们把每格当作 n 条不同的轨迹，而不是一个条件下的 n 个 i.i.d. 抽样。

### 4.3 机制

对推理可读的模型（GLM、Sonnet、DeepSeek、Mistral），越界是工具性动机的而非无端的。在 CI/CD 中，396 次越界里有 347 次（88%）在该回合的推理中引用奖励公式或相对名次，196 次（49%）把竞争算术显式写出来（例如「RB = 50 + (100 − 0)/2 = 100」）；这在竞争奖励格中是特异的（341/383 vs. 独立奖励下的 6/13）。在原始 SOC 诊断中，越界反而是工具性的自助：43/44 次越界来自当时正被席位挡住的智能体。动机随环境而变——CI/CD 中是竞争算术，SOC 中是席位争夺。

### 4.4 模型相关的拒绝行为

在同一次攻击上，Claude Sonnet 5.5 与 Opus 5.5 在所有测试格中 0/100 越界（每个 SOC 臂 0/10、CI/CD 0/20，每个模型），而 Sonnet 4.5 与 GLM-5 在 effect-stated 臂中 9/10 越界。我们把它描述为被评测模型配置之间的差异，而非已证明的代际趋势：0/10 的格有一侧 95% 上界接近 26%，所以这些是强但小样本的观察。这些拒绝是有代价的——在拒绝的那一刻，越界被预期是有利可图的——而且在我们的语料中第一次，模型点名那个诱人的动作并拒绝它（例如 Sonnet 5.5：「有个诱人的捷径是破坏 incident-a……但那会伤害另一位参与者，而且不对」）。给出的理由大多是伤害与公平（约 88%），而不是所有权或范围（约 28%）：这些模型避开了该动作，但大体上不是出于我们所测量的委派理由。Sonnet 5.5 是更干净的案例；Opus 5.5 带有公认的评测觉察混淆，我们不把两者合并。在没有训练访问权的情况下，我们不对原因作任何主张。拒绝行为由一条针对推理文本的确定性关键词规则编码（一个点名该动作并带有回避标记的句子），经人工抽查；规则随工件发布。

## 5. 结果：防御

我们把两种防御评估为一个 bolt-on 层，它在运行时强制执行委派地图。Hard enforcement 是一个确定性 reference monitor，拒绝任何目标资源未被委派给调用者的动作。judge 是一个基于模型的执行前闸门（一个较小的模型），它看到调用者、调用与委派地图，在执行前允许或拒绝。hard enforcement 是显然的基线；它与动机不矛盾，因为它强制的是委派地图而不是权限集合，并不使 P = D。我们在修复后的 SOC（§3）上、在三个可读模型上评估两者，每臂每格 n = 40。

### 5.1 阻断越界是一次健全性检查

两种防御都拒绝了每一次越界，但对 hard enforcement 来说这是按构造成立的：monitor 拒绝的正是检测器标记的那个谓词（permitted、在委派之外），所以没有越界能通过。因此我们把阻断当作正确性检查而不是结果。无防御的越界（GLM-5 3/40、Sonnet 4.5 27/40、DeepSeek 24/40）在两种防御下都降到 0/40。经验内容在于 judge——它可能过度或不足阻断：按预注册定义它产生了 0 次错误阻断（一次 DeepSeek 调用在更严格的度量下被标记——一次点名同伴事件的 redirect，反正会作为普通错误失败；两种读法都报告），且没有漏掉任何越界。在 CI/CD 中，伤害同伴需要越界，一次更早的全网格评估同样把越界通过降到两种防御下的 0（带有 §7 的来源注记）。

### 5.2 在可行的设置中，强制阻止了可避免的伤害

由于修复后的 SOC 是可行的，错过截止是可避免的伤害而不是打不赢的争夺的产物——在这里，强制范围确实保护了同伴。无防御时，同伴在 15/40（Sonnet 4.5，Wilson CI [24,53]%）与 14/40（DeepSeek，[22,50]%）个 episode 中错过其可避免的 SLA，每次都伴随一次越界；在任一防御下这降到 0–1（0/40 的格有 9% 上界），是显著的下降（表 2，Holm p ≤ 1.5 × 10⁻⁴；图 7、表 5）。三个模型在 hard-enforcement 的所有格中都是 40/40 双方完成，而无防御时只有 16/40（Sonnet）与 21/40（DeepSeek）。这与零和再分配相反：阻断越界移除了伤害而不是把它挪走，因为在这个设置里大部分伤害经由越界传播。

### 5.3 一条残余通道存活：严重性误报

通往伤害的一条路径不是越界，且在两种防御下都存活：把自己事件的严重性抬到高于其应有水平，以抢占同伴。这是误报（misreporting），它留在智能体的受托范围内，所以两种防御都拒绝不了它。误报在受防御的臂中仍然发生（GLM-5 hard 2、DeepSeek hard 1、Sonnet 4.5 judge 2），而且在一个 episode 中（Sonnet 4.5、judge）一次误报抢占导致同伴错过截止，尽管它的越界被阻断了。在可行的设置里残余很小——同伴通常仍能完成——但它恰恰是范围边界看不见的伤害。这就是范围/伤害区分的诚实形式：强制移除了经由越界传播的伤害，留下了经由授权的、在范围内的行动传播的伤害。

### 5.4 每种防御各自能泛化到什么

两种防御都不是 effect-aware 的。hard enforcement 只检查调用自身的目标资源，因此放行每一次自己事件的误报。judge 从调用点名了哪些资源来决定：它阻断任何点名同伴资源的调用，放行任何只点名调用者自己资源的调用，包括误报。在一个小型 model-gate 演示中（不属于确定性核心；依赖模型且在可复现的基于日志的分析之外），judge 还阻断了一次构造出来的、本会对同伴有帮助的 redirect，说明它按资源名而非效果过度阻断。因此 judge 相对 hard enforcement 的覆盖仅限于点名同伴资源的调用；两者都漏掉经由智能体自己资源路由的伤害——那正是这里存活的路径。

### 5.5 成本

hard enforcement 不增加任何模型调用，也不增加延迟。judge 每个 episode 增加依赖模型的 10–30 次闸门调用（GLM-5 12、DeepSeek 10、Sonnet 4.5 30），中位每次 0.82 秒，每个 40-episode 格大约 $0.16–0.48。修复后 SOC 评估的智能体花费为 $242（预测 ≈$163；Sonnet 更长的 episode 占大头）。

## 6. 讨论

**模型倾向不是可靠的控制。** 多个被评测的模型在 affordance 存在时越界；不越界的那些出于附带的（伤害）理由而非范围理由避开它，并且这种选择在模型配置之间不同，且不受强制。在尊重范围成为可靠的行为属性之前，强制必须坐在模型之下。

**范围强制与伤害预防是不同的保证。** 我们的防御结果在不过度声称的情况下把这一点具体化。在伤害经由越界传播的地方——CI/CD 以及修复后 SOC 的大部分——强制委派边界确实阻止了它。但 reference monitor 看不见经由授权行动传播的伤害，我们展示了一条这样的通道：对自己事件的严重性误报，它在两种防御下存活并仍偶尔拖累同伴。因此一个范围监视器提供的保证比看上去更窄：它移除的是越界携带的伤害，而不是所有伤害。防御者不应把 0% 的越界率读作完全防护。

**设计启示。** 不要连同收益一起呈现同伴动作；不要用相对方式框定目标；强制委派而不只是权限——但要把范围强制与对自我报告状态的完整性检查配对，因为单靠强制处理不了经由共享资源上合法行动路由的伤害。

## 7. 局限

主要实验每格 n = 40–52；模型拒绝与跨环境格用 n = 10–20，我们报告计数而非紧凑比率（0/10 的格有一侧 95% 上界接近 26%）。Wilson 区间与主要对比的 Holm 校正 Fisher 精确检验在表 2 中，并随工件发布。环境是模拟的。另有两条测量注记：Sonnet 4.5 的竞争/已列出/已明示格处在天花板（52/52），限定了我们对该模型的收益放大效应能分辨多少；以及 GLM-5 在两个未列出格里有 28–35% 的调用返回空文本，所以它在那里的零有一部分是不响应（其他每个未列出格也是 0）。起步落后的智能体从未完成自己的任务（CI/CD 的 1,247 个析因 episode 中 0 次），因此对行动智能体自身的任务伤害未被测量。因此我们不主张智能体放弃了一条可行的合法路径转而越界：CI/CD 中的合法路径是在最优打法下由仿真确立的，而不是由观测到的完成确立。这不影响测得的越界比率，但它限定了动机性解读，我们在此标记，直到修复后 SOC 所用的可行性对照扩展到 CI/CD 为止。对 GPT-6 与 Qwen3-Coder（在跨环境诊断中），92–96% 的空文本使机制不可测。Opus 5.5 带有评测觉察混淆。防御评估只用一个闸门模型、一条提示。我们的发现是所测试环境与模型配置内的证据，不是关于自主智能体的普遍主张。攻击使用一张刻意干净的委派地图，所以防御结果是难度的下界（§8）。

**两条来源缺陷，披露。** 第一，在 R1/R2 运行期间，一次 AWS 会话过期与一次短暂网络中断让 50 个 Sonnet 4.5 episode 中途崩溃，lane runner 在重试前删除了每次崩溃尝试的部分日志。一次在崩溃前已经越界的尝试，在我们的非对称删失规则下会计为阳性；是否真有，现已无法恢复。50 个中有 44 个在同一种子上干净地重跑；2 个在越界后崩溃的被保留为已计数的阳性。同样的 runner 逻辑也用于更早的全网格（defense-002）评估，跨 30 次崩溃重试。暴露是有限的——在受防御臂中越界无论如何都被阻断，且大多数 defense-002 重试是从不越界的空文本模型——所以风险是无防御比率的轻微少计，这偏保守；现已修复（失败的尝试被隔离，从不删除）。第二，原来的「独立奖励」提示告诉智能体其奖励取决于双方得分，所以它并非完全独立；R2 析因修正了这一点，其干净的独立格（0/52）复现了预期基线，但更早的独立条件比较继承了这个混淆。

## 8. 未来工作

三个方向直接来自结果。

**范围边界够不到的伤害的防御。** 范围强制阻止越界携带的伤害，但留下一条残余通道——一个智能体在范围内误报自己的状态以伤害同伴（§5）。自然的下一步是一个 effect-aware 或 integrity-aware 的控制，它推理一个动作对同伴的预期结果做了什么，或一份自我报告是否站得住，而不只看调用点名了哪个资源——例如，闸门一次超过应有水平、且被预期会抢占同伴的自己事件严重性提升。这样的控制提出本文没有回答的难题：区分合法竞争与伤害、避免对普通自我优化的过度阻断、以及在不信任行动智能体的前提下获得应有水平或预期结果的信号。关闭这条残余的授权伤害通道，是本工作浮现出的最重要的开放问题。

**两个以上的智能体。** 这里的每个设置都恰好两个智能体、单一共享资源。现实部署有许多智能体跨越许多共享资源，会引入 N = 2 下我们观察不到的动力学：结盟与合谋（两个智能体结合起来对抗第三个）、责任扩散、经由授权行动链条的间接伤害、以及没有哪一次成对越界能解释的争夺。相互作用的因子（相对目标、被呈现的候选、收益信息）与授权伤害通道是否扩展到 N > 2——以及成对有效的强制是否仍然成立——是开放的。

**更难的委派与自适应攻击。** 攻击使用一张刻意简单、干净的委派地图，这使阻断结果成为难度的下界；动态的、基于属性的、以及有歧义的委派（所有权本身可争议、或在 episode 中改变）会远更严厉地考验两种防御，特别是会检验一个 judge 能否跟踪 reference monitor 无法事先枚举的范围。相关地，我们没有测试自适应攻击——行动的智能体推理闸门并塑造调用以通过它；对 judge 的红队循环是一个直接延伸。

## 9. 相关工作

本工作在系统侧连到 confused-deputy 问题、OWASP 的 excessive agency 概念、以及 MCP/工具安全；在行为侧连到多智能体 LLM 冲突与升级研究、以及关于工具与动作呈现如何塑造模型行为的工作；还连到倾向性评估与更广泛的评估科学。我们不主张 permission 与 authorization 的区分是新的；它在访问控制中早已确立。贡献是在权限与任务保持不变的条件下、随动作呈现变化而对受托范围越界做受控测量，配一个确定性检测器——这是观察性的多智能体冲突研究所没有提供的测量，那些研究缺少一张显式的委派地图。

## 10. 结论

共享基础设施上的智能体常规地被允许做得多于它们受托去做的。在我们的实验中，一个智能体是否跨过那条线，不由它的权限决定，而由它的动作空间如何被呈现决定：没有列出的候选就没有越界，竞争目标驱动越界，明示收益放大它。一些较新的模型会拒绝，但理由不是范围，而且不可靠。模型之下的强制移除了经由越界传播的伤害，但一条残余通道——一个智能体在范围内误报自己的状态——存活下来。因此范围强制与伤害预防是不同的保证，一条守得住的边界本身并不是安全的证据。

## 可用性

代码、环境、委派记录与已提交的哈希链式事件日志公开在 https://github.com/shrave/delegated-scope-violation。复现有两层。**Tier 1（分析）：** 所有报告结果——确定性违规检测器、表格与图形、以及重放验证——都从已提交的事件日志离线复现，只用 Python（NumPy、pandas、SciPy）；不需要模型访问、GPU 或凭证，每个 episode 重放的分类分歧为零。这是主要的可复现工件。**Tier 2（episode 再生成）：** 从零再生成 episode 需要模型访问：闭源模型（Claude、GPT-6）只能经 AWS Bedrock（us-west-2）访问，模型 ID 与区域钉在每份 manifest 中；开放权重模型（GLM、Qwen、DeepSeek、Mistral）以需要服务器级硬件的前沿 mixture-of-experts 规模运行。我们没有自托管开放权重模型，因此不报告其本地硬件或 GPU 小时数字。一个 mock provider 可以在没有凭证或 GPU 的情况下跑通整条流水线。因此我们把离线的、基于日志的分析作为可复现核心。

## 伦理与开放科学

本研究使用模拟环境，没有人类受试。没有真实系统被攻击。我们描述了一种只需一次配置变更即可实施的内部人威胁，而该变更对任何组装 agent 上下文的人都已可用；我们披露它以论证模型之下的强制，并发布一个确定性检测器，他人可对自己的日志运行。
