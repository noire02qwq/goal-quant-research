## 摘要（Abstract）

让语言模型提出改动、跑一个固定实验、凡是让指标变好的就保留——这类 agentic 研究循环在机器学习里很好用，因为更低的验证 loss 通常就意味着更好的模型。在交易研究里，同一个循环是一台生产假发现的机器：一个「让指标变好」的回测，默认就是过拟合、前视、多重比较的产物、零成本的产物，或者只是市场漂移在磨损一个策略。

我们介绍 Autonomous Quant Researcher，一个建立在相反前提上的开源循环：模型可以提议，但只有受信任的代码可以裁决。提议是在固定词表上的严格声明式 JSON，因此没有需要沙箱隔离的模型代码。评估跑在不可变的按时间顺序存放的数据上，分成 discovery、validation 和一个最终的 holdout，而 holdout 只能在一份持久化回执写好之后被打开恰好一次。接受是一组合取的绝对门（扣成本后为正的优势、净 P&L 为正、按周聚类的 bootstrap 下界为正、在更高成本下存活、逐年稳定、样本下限），绝不是一个单一分数。重复与近重复在消耗掉一次试验之前就被拒绝，每一次表述、拒绝、崩溃和结果都记录进一条哈希链式、只追加的账本。

我们报告该系统迄今跑过的每一场战役，涵盖：按实际成交期权 bar 定价的 SPY 与 QQQ 零到期日（0DTE）期权、隔夜 SPX verticals、日线 ETF 规则、流行技术分析脚本背后的前提、Kalshi 加密二元期权、财报期权、场外成交量，以及一场预注册的另类数据战役。大多数假设都失败了，我们也照实报告。有两个结果通过了它们自己预注册的门槛。这个循环在起作用的最清晰例子是一次失败：一个语言模型幸存者以接近 3 的 Sharpe 通过了 discovery 和 validation，却在它唯一一次 holdout 使用中跌到 0.26。我们主张，这样一个循环的科学价值，与其说在于它发现了什么，不如说在于要让它报告一件不存在的事有多难。

## 1 引言

2026 年发布的两个开源项目对 agent 做了一个简单的观察：agent 是便宜的部分，围绕它的循环才是产品。Karpathy 的 autoresearch [9] 让一个 agent 修改单一训练脚本、跑一个固定的五分钟任务、验证指标改善就保留改动、否则丢弃，整夜如此。Greyling 的 Loop Engineering [5] 把循环本身变成一等产物：一份持久契约、明确的预算、确定性的门、一条审计轨迹，以及 maker/checker 分离。

金融是一个那份契约会以特定方式失效的领域。资产定价中的 data snooping 问题由来已久 [12, 16]，针对「同时搜很多条规则」已有正式的修正方法 [6, 24]，而已发表的收益预测因子大多无法通过检验次数修正的证据如今已相当充分 [7, 8]。回测过拟合容易制造、事后难以检测 [4, 2, 3]，而已发表的可预测性一旦为人所知就会衰减 [13]。一个每晚提出数千个假设的语言模型并不能修复上述任何一条，它只是把这些东西工业化了。

近期面向交易与 alpha 挖掘的 LLM-agent 系统——例如 TradingAgents [17]、FinMem [29]、AlphaAgent [15]、R&D-Agent-Quant [11]、树搜索因子挖掘 [25]、基于代码的 alpha 演化 [23]，以及面向股票组合构建的角色化 agent [27]——关注的都是让提议者更好：更丰富的角色、记忆、反思、因子生成与强化。另一些工作则问语言模型究竟能提取出什么，比如它能否跟踪公司披露中不断演化的信号 [28]。

评测一侧的工作更新一些。Deep 等人 [21] 在许多含成本的样本外区间上对可解释假设做 walk-forward 验证；Li 等人 [22] 主张历史回测会让语言模型「时间旅行」到它已经看过的结论上，因而应当改用实盘基准；Yao、Zheng 与 Li 的范围综述 [26] 发现 LLM 交易研究中的执行真实度标准化程度很弱，这限制了比较与复现。与我们目标最接近的是 Gençay [20]：他把泄漏安全与感知搜索的去膨胀（search-aware deflation）内建进一个策略发现系统，并发现没有一个由 LLM 发现的策略能在该 agent 自己的试验次数下通过认证；一个被植入的、Sharpe 达到 35 的前视 oracle 同时通过了 deflated Sharpe ratio 与回测过拟合概率，因此统计修正无法替代结构性的泄漏控制。Chen 与 Pu [19] 通过实时记录 agentic 模型的每日股票评分，在推理时消除前视。来自生产的证据指向同一个方向：在两支在役的 LLM 交易 agent 舰队上，Barton 等人 [18] 发现操作层（仓位约束、渲染出来的选择、订单机制）对行为的影响大于模型选择，而且两支舰队都没有表现出方向性优势。

我们认同 Gençay 的结论，但使用的工具不同：假设以数据形式声明并预注册，holdout 只能花一次，而且每一场战役——横跨期权、微观结构、预测市场与股票——都连同它的拒绝一起被报告。我们聚焦的是循环的另一半。我们的贡献是：关于「决定一个提议是否为真」这一部分的参考设计与开源实现，外加它所做决定的完整报告。

具体而言，本文贡献：

1. 一条声明式的假设边界：模型发出的是数据而不是代码，因此攻击面与可搜索的假设空间都被事先固定（§2.1）。
2. 一个分阶段的证据生命周期：由持久回执强制的一次性 holdout、在消耗试验之前就拒绝重复的准入控制，以及由一组绝对门的合取构成的接受判据（§2.2）。
3. 一条防篡改账本，以及自带来源与权威的可移植发现（§2.4）。
4. 一份完整的战役报告，包括每一次拒绝（§3）。
5. 一份「门在第一时间没有拦住的失败模式」清单，以及每一种失败所迫使的改动（§4）。

引擎是开源的 [1]，附带一个参考任务（mission）和一份可独立核验其账本的公开预注册。市场数据文件不再分发。

## 2 设计

### 2.1 声明式假设边界

在当前 schema（版本 3）中，一个提议恰好有两个字段：hypothesis 与 rationale。hypothesis 包含一个 schema 版本、五分钟常规时段网格上的一个入场分钟、一个在受批准的因果观测之上、有界的布尔信号表达式（开盘以来的收益、两个更早时点之间的收益、入场前的首次触及），以及恰好一个受批准的、有界维度的 defined-risk 期权结构（call debit spread 或 put credit spread）。受信任的函数负责解释这份声明。带有额外字段、无效 JSON、不支持的词表、畸形的时序、过深的嵌套或越界参数的响应，在任何科学评估之前就会被拒绝。

这条边界取代了一个更早的设计（保留在仓库中）：在那个设计里，模型返回一个可执行的 Python 候选。那个设计需要沙箱（剥离凭据、拒绝 import 与能力、内容哈希的评估器），而且仍然让候选得以表达评估器没有预料到的东西。删掉可执行字段是把问题移除，而不是把它围住：没有东西需要沙箱，而且每一个可接受的假设，按构造就是评估器知道如何定价的假设。

### 2.2 分阶段证据与一次性 holdout

各阶段存储从同一份历史数据源一起物化，但每个访问能力只解析自己的阶段，每个存储都带一个内容哈希和一个清单哈希。每一场战役冻结自己的窗口。在使用日线与建模数据的参考 SPY 任务中，discovery 是 2016–2021，validation 是 2022–2024，最终 holdout 是 2025 年起。按成交期权 bar 定价的 0DTE 战役从那些 bar 出现之时开始：discovery 是 2024-01-19 到 2025-08-05，validation 是 2025-08-06 到 2026-02-05，holdout 是 2026-02-06 到 2026-08-10。

**在第一个结果之前冻结。** 任务、策略、词表、解释器与评估器的版本、各阶段清单、基础与抬高的成本、试验预算、多样性规则与门，都在第一个提议被评估之前被哈希进一份战役契约。改动其中任何一项都会创建一场新战役；一场非终态的战役不能在改动后的语义下继续。

**准入。** 表述（formulation）与科学试验分开计数。无效文档会被记录，但不消耗试验。语义重复与近重复（同一个想法上拧动了一个数值旋钮）会被拒绝，而且族配额（family quota）每个描述符族最多准入两个候选。因此一份 50 次试验的预算买到的是 50 个不同的想法，而随任何结果一起报告的试验次数就是实际试过的次数。

**入围。** discovery 预算关闭之后，只有通过了每一道 discovery 门的候选才有资格。协调者按它们最弱的门组件排序、偏好不同的簇、最多冻结三个并对入围名单哈希。validation 只评估那一组，并把 5% 的尾部概率除以入围名单的大小。

**holdout。** 普通 worker 停在 `holdout_ready`，打不开最终阶段。只有在一份不可逆的回执被持久写入之后，holdout 访问才会被解析；回执之后的崩溃仍然会消耗掉 holdout，且不能重试。预算耗尽是一次暂停，绝不是一次成功。

### 2.3 门，而不是分数

每个阶段都必须通过每一道适用的门：

- 扣除基础成本后的绝对优势 > 0；
- 基础成本下的平均净 P&L > 0；
- 净 P&L 的按周聚类 bootstrap 下界 > 0（2,000 次确定性重抽样，按 ISO 周聚类；参见 block bootstrap [10]）；
- 抬高成本下的平均净 P&L > 0；
- 指标有限、行已定价；
- 样本下限。在参考 SPY 任务中，discovery 是 120 笔交易与 40 个有效周；validation 是 60 与 24，且 2022、2023、2024 每年都要有证据，每年至少 15 笔交易与 8 周，且不得有负年份；holdout 是 30 与 12。

下限随战役的窗口伸缩，并冻结在它的契约里。窗口更短的成交 bar 0DTE 战役要求 40、15、15 笔交易。一个排序分数——取绝对优势、bootstrap 界、抬高成本 P&L 与最差年份四者的最小值——只在已通过的候选之间做选择，它不能准入任何一个。一个相对对照的指标会被计算，但仅供诊断，因此一个疲弱的对照救不了候选。

建模的期权价格不是市场价格。真实的 OPRA 证据是一道独立的带类型的门，有它自己的覆盖下限与状态（unavailable、insufficient_coverage、failed_evidence、passed）；回放只消费经过哈希核验的报价产物，没有回退价格源。

### 2.4 账本、来源与权威

每一个事件（表述、准入决定、试验、崩溃、阶段转移、holdout 回执）都被追加进一条账本，其中每条记录都带有其前驱的哈希。编辑、删除或重排一个事件会让该战役 fail closed。一个存活下来的发现被导出为可移植的 JSON，且只由已冻结的聚合证据构成：契约与清单哈希、各阶段证据、局限与失效条件，以及一枚不可变的权威戳记（`research_only`、`execution_authorized: false`）。任何在下游消费该发现的东西，都确切知道自己手里拿着的是什么。

同一套机制为数据尚不存在的战役支持预注册：一份规范与将要计算其结论的代码用 SHA-256 绑进账本，带类型的数据需求在满足之前拒绝运行，而每场战役只被评判一次，回执写在读取任何数据之前 [14]。

### 2.5 模型无关性

评估器是确定性的 CPU 代码；只有提议者需要模型。任何 OpenAI 兼容的端点都可以提议。参考配置是一个本地服务的 70 亿参数代码模型。由于评估器不依赖谁在提议，换模型不可能移动任何指标，只能移动候选。

### 3.1 一个语言模型幸存者遭遇它的 holdout

最有教益的单个结果是一场 QQQ 0DTE 战役：语言模型提议者在它的第十三次运行中产出了一条规则——在周一和周二、当权利金超过宽度的 10% 时卖出 near-money put credit spread。在上述成交 bar 窗口上、并按该战役自己的下限（40、15、15 笔交易），它通过了每一道 discovery 与 validation 门（表 2）。在明确指令下，holdout 被用掉了一次。九道 holdout 门中过了八道：规则保持净为正，扛住了成本翻倍和剔除最好一天。但期望值跌了约 90%，Sharpe 跌了一个数量级，而且 holdout 窗口有一半是净为负的。该规则被拒绝，holdout 窗口如今对这个候选被永久标记为已消耗。

**表 2：QQQ 语言模型幸存者在三个阶段上的表现。**

| 指标 | Discovery | Validation | Holdout |
|---|---|---|---|
| 每笔净收益（% of width） | +5.69 | +4.82 | +0.52 |
| 净 Sharpe | 2.94 | 3.34 | 0.26 |
| 交易笔数 | 221 | 43 | 72 |
| 状态 | passed | passed | rejected |

有两点对设计很重要。第一，样本内的数字并不处于边缘：一个以 validation Sharpe 高于 3 为接受条件的循环，会把这条规则 promote 出去。第二，该战役的冻结规范当时被写到了一个临时路径上，在请求 holdout 时并不在磁盘上。与其在一个猜测出来的规范下评估，我们把它重建出来、并对照已经消耗掉的两个阶段做了核验（discovery 的 Sharpe 与记录值在小数点后六位一致，数据集哈希与 staging 清单一致），然后才读取 holdout。战役契约如今与账本一起持久化，因此这种情况不会再发生。

### 3.2 0DTE put 信用溢价：真实，但还不够

无条件的 SPY 0DTE put credit spread（宽度 5、空头行权价价外 5 点、10:00 ET 入场、持有到结算）在往返成本为宽度的 0.5% 时通过了每一道 discovery 与 validation 门，每个交易日分别为 +55.7 与 +71.6 个宽度基点，毛胜率 95.2%。随后三个各自预注册为新契约的跟进研究，检验了这究竟是一条策略还是一种副产品。

**漂移。** 把每个交易日的 P&L 对同期 SPY 自身收益回归，会把 13–30% 的 payoff 归因于市场方向。drift-neutral 残差在两个切分中都为正（毛额 +74 与 +100 个宽度基点），但它的周 bootstrap 下界在两个切分中都略为负。按在归因运行之前就写下的规则，该结构不被 promote。

**几何结构。** 在五组预注册几何结构中，溢价对 moneyness 单调：offset 2 优于 5 优于 10，而 offset 10 为负。最好的单元 w5/o2 通过了除一个之外的所有条件——discovery 的原始 bootstrap 界，差 1.35 个宽度基点。一次以百分比计的、针对同一单元的预注册 QQQ 复现，在幅度相近的情况下恰好未通过同一个条件。两条行情上最差的 discovery 周是同样的日历冲击（2024 年 4 月、2024 年 8–9 月、2025 年 3–4 月）。

**条件化。** 一个在前一日涨跌至少 1% 之后跳过入场的过滤器（按约定选定，而非拟合），让每一个 bootstrap 都更差。亏损来自冲击的第一天，它跟在一个平静日之后、无法从前一日信息预测；到第二天波动率已经重新定价，卖出反而最划算。

诚实的总结是：near-money 0DTE put 溢价是真实的，在两个标的上有同样的形态，大部分不是漂移，并且是靠吸收不可预测的第一天冲击来赚取回报的。那个预注册门槛要求在一个包含三次此类冲击的窗口上，周均值的第五分位为正——它没有达到，而且门槛没有被移动。为完全满足各门所需的盈亏平衡入场成本落在宽度的 0.5% 到 1.0% 之间，这就把一个关于策略的开放问题，变成了一个关于执行的可测量问题。

### 3.3 技术分析与日线规则战役说明了什么

在 232 个单元的日线规则网格里，全部四个 discovery 通过者都在两个方向上用了同一个特征：20 日下跌之后做多，以及 20 日上涨之后做多。一个「反过来也同样通过」的条件不携带任何信息；通过的是在持有这些 ETF 有回报的窗口里的多头一侧。门抓住了样本与稳定性问题，但它们本身无法发现整个 discovery 窗口都指向同一边。三个入围单元在 validation 中都未通过每一道表现门。在技术分析战役里，一个前提（回归通道）通过了全部九道 discovery 门，随后在 validation 中每个交易日亏 22 个基点；而且每一个前提都跑输单纯的做多。

### 3.4 活下来的东西

有两个结果通过了它们自己的预注册门槛，正在另行撰文。一只股票在场外成交的成交量占比（由公开 FINRA 数据构建）在 1、5、20 天上都有负的信息系数（t 在 −3.1 到 −5.8 之间），在 2021–2026 每一个日历年都为负，集中在最高的十分位，且对规模与短期反转稳健；厂商发布的「dark pool index」什么都预测不了。在特异性跳空战役中，预注册的延续假设被拒绝，而市场级 crash 日当天输家的反转通过了每一道门。我们把两者都作为带局限的研究发现来报告，而不是作为策略。

## 4 门最初没有拦住的失败模式，以及每一种带来的改动

**把漂移当成 alpha。** 一个无条件的 long-delta credit spread，无论是否有任何定价错误，都会收下市场的向上漂移。一个隔夜 SPX 1DTE 平值 call debit spread 以 2.27 的周 Sharpe 通过了每一道 validation 门；它 validation payoff 的 56% 是标的自身的变动，而残差的 bootstrap 界为负。一个预注册的漂移对照（把每笔交易对同一持有期内标的的变动回归，再对残差设门）如今是这一族门槛的一部分，漂移分解本身被携带在快照里，而且每场战役都能拿到相对基准的 payoff。

**单向的 discovery 窗口。** 在一个窗口上评估的门，看不到这个窗口只指向一个方向。与网格一起记录下的规则是：一个条件要连同它的反面一起读，而一对都通过的组合是多头一侧的伪影，不是信号。

**假设的成本，而不是测量的成本。** 有两个候选是被一道「成本翻倍」的门杀死的，而那个成本没有任何人测过；还有一次 holdout 在它的成本前提被测量之前就被花掉了。那次隔夜 SPX 的 promote 是在时间压力下、用一个夜晚的成本采集花掉的，回来时是被拒绝的。如今战役会把盈亏平衡成本与结果一起报告，而且写下来的规则是：实测的入场成本必须先于任何 holdout 的消耗。

**经由特征的前视。** 138 个 Kalshi 假设中唯一那次形式上的通过，是以它所预测的同一窗口内的成交量为条件的。以窗口内信息为条件的单元如今被标记为 descriptive-only，不能计为证据。

**丢失的规范。** 见上面的 holdout 案例；契约如今与账本一起持久化。

**白白花掉证据。** 当每一个前提在 validation 中都已经是负的时，TA 的 holdout 被留着不读：没有任何结果可能改变，读它只会毁掉一个干净的窗口。

## 5 局限

这个循环让报告一件不存在的事变难了；它并没有让真的东西容易被找到。它的词表是刻意做小的，一个在词表之外的假设，在受信任的代码被扩展之前无法被检验。若干战役使用短样本（例如 46 天的 Kalshi 数据、60 个周末的 ETF flow），它们的零结果既是对市场的陈述，同样也是对检验功效的陈述。2024 年之后的期权结果没有覆盖 2022 年那种熊市。有些建模价格仍被留在拿不到真实报价的地方；那些战役会明说。若干战役中的成本是带盈亏平衡说明的假设，而不是测量。最后，本文由该系统的作者撰写；每个数字背后的完整战役记录可向作者索取。

## 6 结论

量化金融中的研究循环，应当首先按「它有多难被愚弄」来评判，其次才按它发现了什么来评判。让模型提议数据而不是代码、在物理上分隔阶段、让 holdout 只能花一次、只接受一组绝对门的合取、在重复消耗试验之前拒绝重复、并把每一次失败都留在一条链式账本里——这些合在一起产出的系统，最常见的输出是一个记录完备的「不」。我们认为那才是正确的基率，而把它发表出来正是重点所在。
