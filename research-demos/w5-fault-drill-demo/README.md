## 1. 验证目标（对应 brief-plan 设计问题）

1. **故障注入三路径验证清单可执行化**（§12.0 W5 研究项）：改坏代码 / 重启 / 改目标三条路径各配"注入 → 观察 → 断言"脚本——改坏代码 → 失败不终止、生成修复任务重进循环（§6.2 韧性）；重启 → 恢复扫描从一致状态继续、**已完成步骤零重跑**（0002 幂等回执）；改目标 → 状态机显式转换 + GoalEvent 审计，队列任务重定标。
2. **群组幂等追加条**（§12.2 W5）：成员 Run 崩溃/消息丢失时群组**不重复执行已完成步骤**——复用 0002 consume-once 语义，注入后断言回执不重放。
3. **演示数据固定化**（§12.0 W5 研究项 + §12.1 W5 方向①）：固定窗口 + 固定 seed 的合成行情夹具（防现场翻车），同一 seed 两次生成逐字节一致（哈希断言）；口径与"固定窗口 + 模拟盘 T+1 前向"的汇报要求对齐。
4. **T3 网格 / T4 经典海龟模板**（§12.0 W5 交付）：以可运行策略形态进本 demo 的固定化回测（模板代码 + 参数白名单），与 T1（w3 demo DualMA 形态）同构验收。
5. **注入梯度复用 W1 口径**：故障注入按 takeover-depth 式梯度分级（轻→重），每级有预期观察，不做一次性毁灭测试。

**范围边界**：harness-hub 集成验收按 @user 指令搁置——本 demo 全部为**独立进程内演练**（复用 w1-recovery-demo 已验证的认领/回执/fencing 原语），平台侧集成验收留待搁置解除。
